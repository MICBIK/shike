**未做实机 VoiceOver 开启走查**：走查时段产品负责人正在本机使用（多会话并行），VoiceOver 全屏接管干扰过大；改用 **AX API（Accessibility）树审计**——即 VoiceOver 的数据源——做同等覆盖的标签/可达性检查。**VO 实听项**（朗读语序、转子发现性、自定义动作的可达手感）留待阶段 5 人工验证，已在 §5 列为验证项。

动态走查受三重环境干扰（如实记录）：①同机并存卡C 性能实例，⌥N 热键存在双实例竞态；②显示状态（空间/全屏/菜单栏隐藏）在走查中多次漂移，两次坐标类点击落空后即停止盲点；③设置窗口 TabView 等结论均在干扰间隙以 AX 复核。以上不影响已采集证据的有效性（每条均标注归属实例与采集方式）。

## 2. 发现清单 · VoiceOver 标签与可达性

> 置信度标注：【动】=动态 AX/截图证实；【静】=代码核对证实。行号以当前 HEAD（710f2f1 时代）为准。

### P1（主路径语义缺失）

**A1 · 面板快速输入框对 VoiceOver 无名称**【动】
- 现象：面板聚焦输入框时 AX 元素为裸 `AXTextArea`，title/description/help 全空（AX 树实测）。占位文案「记点什么…(⇧⏎ 换行)」由 `PlaceholderNSTextView` 自绘（`CaptureTextView.swift`），不进 AX 树。
- 影响：VO 用户呼出面板后焦点落在输入框，只听到"文本区域"，不知道这是干什么的、支持什么快捷键。这是应用的第一入口。
- 修复：`makeNSView`/`updateNSView` 里 `textView.setAccessibilityLabel(placeholder)`（随模式切换更新文案）；顺手补 `accessibilityHint`（⇧⏎ 换行、Tab 切模式）。**约 0.5h**。

**A2 · 待办完成圆圈按钮无动作语义**【静，两处】
- 现象：`Panel/TodoListView.swift:146-152` 与 `MainWindow/MainTodosView.swift:428-433` 的勾选按钮仅 `Image(systemName: "circle"/"checkmark.circle.fill")`，无 `accessibilityLabel`/`accessibilityValue`。VO 读 SF Symbol 默认描述（"圆形"），且完成态切换无播报变化。
- 影响：勾选/勾回是待办流的核心动作，VO 用户无法从朗读中分辨"这是勾选"以及"是否已完成"。
- 修复：两处补 `.accessibilityLabel(勾选完成/标记未完成)` + `.accessibilityValue(已完成/未完成)`。**约 1h**。

### P2（可达性缺口）

**A3 · 搜索框无 AX 名（三处）**【动（主窗口便签侧实测）+静】
- 现象：主窗口搜索框 AX 树为裸 `AXTextField`（全空），而旁边装饰性放大镜图标反而带 SF Symbol 默认描述"搜索"——语义错位。`MainNotesView.swift:256`、`MainTodosView.swift`（同款）、`Panel/SearchView.swift:19`（placeholder「搜索」）三处同构。SwiftUI macOS 上 TextField placeholder 不会自动成为 AX 名。
- 修复：三处补 `.accessibilityLabel(...)`（复用既有字符串 `main.notes.search`/`main.todos.search`/`search.placeholder`）。**约 1h**。

**A4 · 面板顶栏搜索按钮无显式标签**【静】
- `Panel/PanelView.swift:125-131` 图标按钮（magnifyingglass）无 `accessibilityLabel`，依赖 SF Symbol 默认描述。同文件内的识别取消按钮（:289）已示范了正确做法。**约 0.25h**。

**A5 · 行"单击编辑"不暴露为 AX 动作**【静，5 处】
- 现象：面板便签行（`NoteListView.swift:125`）、主窗口便签行（`MainNotesView.swift` display 分支 onTapGesture）、面板待办标题（`TodoListView.swift:175`）、搜索结果行（`SearchView.swift:69/85`）、卡片正文双击（`StickyCardPanel.swift:169`）均为 `onTapGesture`，AX 树中只是静态文本。
- 影响：VO 用户无法发现"单击可编辑"；右键菜单有「编辑」冗余路径（经 VO 动作转子可达），故为可用但不可发现。
- 修复：这些行补 `.accessibilityAddTraits(.isButton)` + `.accessibilityAction(named: 编辑…)`（或直接改 Button 包裹）。**约 1.5h**。

**A6 · 主窗口行删除按钮 hover 才存在**【静】
- `MainNotesView.swift:458-470`：删除按钮在 `if isHovered` 分支内条件渲染，非悬停时根本不在 AX 树里。右键菜单有删除冗余。修复：改为常驻 + `.opacity`（或低视/VO 环境下恒显）。**约 0.5h**。

**B1 · 面板尺寸把手纯拖拽**【静】
- `PopoverResizeHandle.swift`：DragGesture 手势，无键盘等效、无 AX 角色；22×22 热区对运动障碍用户也偏小。修复：把手加 AX 可调整动作（增减步进），或在设置-通用提供面板尺寸数值项。**约 1–2h**。

**B2 · 卡片移动/缩放完全无键盘路径**【静】
- `StickyCardPanel.swift:431-509`：移动走 `window.performDrag`、缩放走 `nextEvent` 鼠标事件循环；卡片窗口 `canBecomeKey=false`（编辑态除外，:39），意味着**除编辑文字外，键盘/VoiceOver 无法对卡片做任何几何操作**。工具栏按钮本身标签完备（ADR-026 成果），唯几何操作例外。
- 修复：给拖动条与缩放把手加 AX 可调整动作（方向键步进移动/缩放），或卡片 ⋯ 菜单加「位置重置」「尺寸」数值项。**约 2–3h**。

**B3 · 设置窗口六个分页折叠进溢出菜单且 AX 不可见**【动+静】★建议提前修
- 现象：默认 460pt 宽度下，`SettingsView` 的 TabView 分页（通用/卡片/提醒/快捷键/数据/关于）全部折叠进工具栏「»」溢出按钮——AX 树的工具栏只剩 `AXPopUpButton "更多工具栏项"`，六个分页项对 VoiceOver **不可见**；视觉上也看不到分页栏（截图证实）。切分页必须鼠标点「»」再选菜单项，键盘不可达。
- 修复（三选一）：加宽窗口到 ~560pt 让分页全显；或改用固定 `.tabViewStyle`；或阶段 4 扩设置窗口时直接改侧栏式。改布局参数 + 六分页复测。**约 0.5h**（方案一）。
- 备注：这是 UX 级问题而不仅是辅助功能问题；阶段 4 设置窗口还要加内容，建议开工前先修。

**B4 · 弹出面板不在应用的 AX 窗口列表**【动】→ 列为验证项亦可
- 现象：面板打开、焦点在输入框时，应用 `AXWindows` 仍返回空（三次实测一致）。NSPopover 宿主的 SwiftUI 内容可经焦点链/坐标命中到达，但不进窗口列表——VoiceOver 的窗口导航（VO-F1-F2）看不到面板。
- 影响：面板打开方式不当（如经状态栏图标点击、未形成焦点）时，VO 用户可能"找不到"面板。⌥N 呼出即聚焦输入框的路径可用。
- 修复：阶段 5 先调研（popover→NSPanel 承载复测 / 显式 accessibilityElement 容器）。**调研 2–4h**。

### P3（打磨项）

**A7 · 卡片颜色/层级菜单的当前值不进 AX**【静】：`StickyCardPanel.swift:245-289` 菜单标签静态（"颜色"/"切换显示层级"），当前是"黄色/悬浮"VO 听不出。补 `.accessibilityValue(...)`。**约 0.5h**。

## 3. 系统设置联动验证

### 3.1 减弱动态效果（reduceMotion）——判定：达标

覆盖面盘点（全仓动效逐处核对）：

| 位置 | 动效 | 降级方式 |
|---|---|---|
| `Support/Motion.swift` | 统一闸门 | `Motion.standard/gentle` 在 reduce 时返回 nil（直切） |
| PanelView:41,49,50,195 | 反馈条/识别 chip/搜索切换/聚焦描边 | 均经 `Motion.standard` |
| NoteListView:146,151 / TodoListView:205-212 / MainTodosView:459-460 / PaperCard:59-60 | 行入场/勾选/hover/高亮 | 均经 `Motion.gentle` |
| UndoBar:84-85 | 5 秒倒计时细条 | `guard !Motion.reduce` 显式跳过（全仓唯一 `withAnimation` 裸调用，且在闸内） |
| CardManager:446 | 卡片自动隐藏动画 | `if Motion.reduce` 跳过 |
| StickyCardPanel:124,206 | 编辑态切换/工具栏提亮 | 均经 `Motion.standard` |
| PopoverController:61 | 面板弹出动画 | `popover.animates = false`（本就无系统动画） |

全仓 17 处动效调用点全部经 Motion 闸门，另有 2 处（UndoBar 倒计时条、卡片自动隐藏动画）以 `Motion.reduce` 直判跳过——无漏网裸动画。**遗留**：实机开启后的逐界面体感确认（纯视觉确认，无自动化手段），列入 §5 验证项。

### 3.2 减少透明度（reduceTransparency）——判定：部分（依赖系统默认）

全仓无 `accessibilityDisplayShouldReduceTransparency` 响应代码。涉及面：
- `.thickMaterial`×2（PanelView:54、PaperSurface.swift:13）——SwiftUI 材质对系统开关自动降级为不透明（系统行为，本夜未实机截图确认）；
- 自绘半透明层**不响应**：纸感渐变 `opacity(0.94)`（PanelView:53）、输入容器 `CardBackground.opacity(0.72)`（PanelView:181/MainNotesView:277）、accent 低透明垫色与描边（0.10–0.22 多处）。
- 建议：阶段 5 显式响应——reduce 透明度时给自绘层叠实心底、去低透明垫色。**约 2h**。

### 3.3 增强对比度（increaseContrast）——判定：未处理

全仓零响应代码。低对比元素清单（开启后仍维持原样）：`.secondary/.tertiary` 次级文字（大量）、卡片工具栏常驻 55% 透明度（`StickyCardPanel.swift:205`）、未聚焦描边 `accent.opacity(0.22)`（PanelView:186）、`CardMeta` 时间小字。建议：以 `NSWorkspace.accessibilityDisplayShouldIncreaseContrast` 为闸，提亮描边（≥0.45）、工具栏常驻全亮、次级文字升一级。**约 2–3h**。

（实测说明：`defaults write com.apple.universalaccess` 直写不实时生效，本夜以代码核对为准；三个开关的实机逐界面截图对比列入 §5 验证项。试验值已还原。）
