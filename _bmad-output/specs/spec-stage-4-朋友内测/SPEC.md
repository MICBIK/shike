# 阶段 4 · 朋友内测（v0.5）

## Why

阶段 0–3（含 3.5）让拾刻成了自己每天能用的便签/待办菜单栏应用，但它还到不了别人手里：没有安装包、没有更新通道，数据出事只能自己翻目录。本阶段面向朋友内测，目标（docs/02）：**朋友能从 GitHub 自助安装、收到更新；数据可以找回、可以导出。**

- 发布链路一条龙：S4-00 已验证"ad-hoc 签名 + Sparkle EdDSA"可行（ADR-032）→ S4-03 一条命令打包发布 → S4-02 应用内自动更新 → S4-04 README 安装说明。朋友侧"下载 → 放行 → 用起来 → 收到更新"全链可用。
- 数据安全感补完：最近删除加保留期自动清除（S4-05）、备份露出设置面（S4-07）；导出已在 3.5 提前交付（S4-06 只余设置入口与验收走查）。
- 设置窗口收口完整六分页（S4-01，开工首项先修可访问性审计 B3 的分页折叠）；首次引导与反馈渠道面向新用户（S4-08/S4-09）。

技术地基（已就位）：Sparkle 2.10 全链参数与限制见 ADR-032；启动顺序"检查更新"插槽已预留（04 §6.1）；`TrashRepository` 与回收站观察流（3.5）、`BackupService` 与每日轮换（阶段 0）在库；仓库问题模板已附带（`.github/ISSUE_TEMPLATE/` bug/idea 两模板）。

- **CAP-6** 最近删除 · 保留期自动清除（S4-05 · Story 6.6）
  - **intent:** 删过错东西的人能在保留期内找回已删除内容，超过保留期的由拾刻自动清掉——既有后悔药，又不留无限增长的数据尾巴。
  - **success:**
    - 设置-数据页新增"最近删除"节：保留期 7 / 30（默认）/ 永不 三选一，即时生效并持久化（偏好键 `trash.retentionDays`，0 = 永不，04 §5.5 已登记）；文案说明"超过保留期将自动清除，不可恢复"。
    - 超期清除在**启动时 + 每日跨天**（`NSCalendarDayChanged`，与备份同一节奏）后台异步执行，不影响冷启动预算（04 §10，v0.4 基线 250 ms）：物理删除 `deletedAt` **严格早于**保留期截止时刻的软删行（恰好等于截止的行不清）；语义与现有"永久删除"一致（便签级联卡片记录、待办通知已在软删时取消）。
    - 保留期切小后，下次扫描按新值执行（已超期的立即清除）；"永不"时短路，不运行任何清除。
    - 清除单事务、失败只写日志不打扰用户；主窗口回收站随同一观察流即时反映，无需刷新。
    - 数据层清除方法（`TrashRepository.purgeExpired(before:)` 或同语义）L1/L2 全覆盖：恰好等于截止不清、两表、级联、"永不"短路；扫描条件与"永久删除"同一套谓词（防误伤钉死在库层测试）。
    - 现有回收站/恢复/撤销语义零回归（C3 家族既有测试全绿）；清除前不做提醒（超出 docs/02 范围，如需另立故事）。

- **CAP-8** 备份设置（S4-07 · Story 6.8）
  - **intent:** 在意数据的人能在设置里看到和管理自动备份，知道备份真的在发生、出事时知道去哪找。
  - **success:**
    - 数据页"备份"节：保留份数选择（范围 **1–30**，默认 7，绑定既有 `backup.keepCount`），改后下次轮换按新值生效；迁移前备份（`shike-before-*`）不占保留计数（既有语义不变）。
    - "立即备份"按钮触发 `backupNow()`；进行中防重入（与每日备份互斥串行，BackupService 内部单一执行位；库层备份本身原子兜底）。
    - 备份状态行：成功态唯一真相 = 扫 `Backups/` 中 `shike-YYYY-MM-DD.sqlite` 文件名日期显示"上次成功备份"；最近一次尝试失败时显示"上次备份失败：原因"（`ErrorText` 中文映射，03 §14）。**失败态定死为会话内内存回传，不持久化、不跨启动显示**（下次备份失败会重新出现）——不新增偏好键，避免双真相。
    - "在访达中显示备份"在访达中定位 `Backups/` 目录（调试数据目录覆盖时显示实际目录）。
    - 备份动作与状态展示不阻塞主线程；失败不打扰（与既有"只写日志"策略一致，设置面是唯一露出点）。

    - 小窗口三步，与 03 §12 一致：①拾刻住在菜单栏（箭头指向图标）+ ⌥N 随时呼出、可在设置修改；②便签和待办按 Tab 切换；③试一试"明天上午十点开会"看时间被识别。
    - 第 3 步引导用户实际创建一条带时间待办（按钮代填文本到面板待办模式，用户回车保存）；创建成功即走既有首次请求通知权限链路（S2-10）；**权限请求不得早于用户主动创建**（TCC 一律用户亲手授予）。
    - 随时可"跳过"：任意一步关闭即完成并标记 `onboarding.completed`，不再自动弹；最后一步"完成"同样标记。
    - 关于页"重新打开引导"：重置标记并弹出；重开后再完成/跳过状态一致（重开路径不检查条件①，数据不是新建也能弹）。
    - 引导窗口视觉与拾刻一致（厚材质、圆角）；"减弱动态效果"时无动画直切（复用 Motion 降级）；引导期间呼出面板/热键不与引导窗口抢焦点死锁（引导窗 + 面板 + 卡片三层同场的时序以真机验收为准）。
    - 真机三场景各验一遍：全新安装（自动弹）、升级安装（不弹）、关于页重开（弹）。

- **CAP-10** 反馈渠道（S4-09 · Story 6.10）
  - **intent:** 遇到问题或有想法的朋友一键就能带着版本信息到正确的地方反馈，不用学 GitHub 的规矩也能把话说清楚。
  - **success:**
    - 关于页"反馈问题"按钮：打开 GitHub Issues 新建页并**预填版本信息**——app 版本（含构建号）、macOS 版本、机型；预填走 issue form 字段参数（与已附带模板 `.github/ISSUE_TEMPLATE/` 的字段 id 对齐，实现时实测 GitHub 端回填效果）；模板文件头标注"字段 id 与 App 预填耦合，改动需同步 S4-09"。
    - **隐私红线：**预填内容不含任何便签/待办内容、不含数据目录路径（路径含用户名）；仅系统与应用版本事实。
    - bug 模板的"版本信息"字段与预填内容一一对应，不出现模板要而预填没有的空档。
    - 打开动作失败（无默认浏览器等极端情况）如实反馈并写日志（`ui` category），不静默。
    - URL 组装（含转义）为纯函数，L2 单测覆盖。

## Constraints

- **沿用阶段 0–3 全部硬约束：**模块边界与导入检查（CI checks）；ShikeKit 不引入 AppKit/SwiftUI；无单例、依赖注入；错误只抛 `ShikeDataError`、不 `try?` 吞写入；文案键集中 xcstrings（`extractionState: manual`）；"警告即错误"只在 CI（ADR-019）；GPL 文件头；新文件先 `xcodegen generate`。
- **新依赖仅 Sparkle 2.10.0（MIT）：**锁定精确版本、NOTICE 登记、只进 App 目标；升级依赖单独提交并记录原因。
- **偏好键口径：**新增 `onboarding.completed`（Bool，默认 false）；`trash.retentionDays`（0 = 永不）与 `backup.keepCount`（默认 7）已登记沿用；更新侧以 Sparkle 自持键（`SUAutomaticallyCheckForUpdates`）为唯一真相，04 §5.5 登记时标注来源；快捷键由 KeyboardShortcuts 自持（`newNote`/`newTodo`）。凡落新键同步 docs/04 §5.5。
- **验收分层：**L1/L2 覆盖多热键注册/派发、超期清除谓词与边界、备份互斥与结果回传、引导步骤状态机（推进/跳过/重开/触发条件，注入时钟）、URL 组装转义；L3 真机覆盖 ⌥N 回归（含 TCC）、更新窗口前置（LSUIElement）、升级后数据完整、全新安装/升级/重开引导三场景、README 放行全流程。
- **对外副作用只发生在发布窗口：**`scripts/release.sh` 默认只构建；`--publish` 才创建 Release 与推 appcast；发布由产品负责人验收后在 main 打正式标签执行。
