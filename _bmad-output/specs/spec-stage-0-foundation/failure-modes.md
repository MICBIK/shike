# 失败模式与处理（S0-05）

原则：宁可明确报错，也不静默丢失（01 §4、ADR-013）。失败的事务整体回滚，已经提交的数据由 SQLite 保证完整。流程图见 architecture-diagrams.md §4～§6。

| 情况 | 如何发现 | 用户看到 | 数据保证 | 测试 |
|---|---|---|---|---|
| 数据目录不存在 | `open` 时检查 | 无（自动创建） | — | L1 |
| 数据目录无法创建或没有权限 | 文件系统错误 | 打开失败提示，原因为"没有访问数据目录的权限" | 不写任何文件 | L1 |
| 数据文件损坏 | SQLITE_NOTADB / CORRUPT | 打开失败提示，原因为"数据文件已损坏" | 原文件不改动、不删除、不重建 | L1 |
| 迁移前备份失败 | 迁移前备份抛出错误 | 打开失败提示，附原因（如磁盘空间不足） | 不执行迁移，库保持原来的版本 | L1 |
| 迁移失败 | 迁移抛出错误 | 打开失败提示，附原因 | 事务回滚，库保持迁移前的状态；迁移前备份仍在 | 代码评审（迁移在单个事务中执行） |
| 库来自更新的版本 | `hasBeenSuperseded` | 打开失败提示，原因为"数据文件来自更新版本的拾刻" | 不执行迁移，不写入 | L1 |
| 模拟打开失败 | `-ShikeSimulateDatabaseOpenFailure YES` | 首次打开失败时的提示 | — | L3（验收第 6 条） |
| `-ShikeDataDirectory` 路径无效 | 展开 `~` 后仍不是绝对路径 | 打开失败提示，原因为"数据目录路径无效" | 不会退回默认目录，避免误碰真实数据 | L1 + L2 |
| 模拟写入失败 | `-ShikeSimulateWriteFailure YES` | 与真实写入失败相同 | 不写库 | L1；阶段 1 起用于 L3 |
| 写入失败 | 仓储抛出 `writeFailed(原因)` | 顶栏下方的红色提示条"保存失败：原因"，附"重试"；输入保留（S1-04 起） | 该事务整体回滚 | L1 + L2 |
| 读取或观察失败 | 观察流以 `readFailed(原因)` 结束 | 红色提示条"读取失败：原因"，附"重试"（重新订阅） | — | L2 |
| 备份失败 | `backupFailed(原因)` | 不打扰用户，只写日志；S4-07 起在设置中显示 | 主库不受影响，不留下半成品 | L1 |
| 备份中途退出 | 下次备份时发现残留的临时文件 | 无 | 先清理残留，再重新备份 | L1 |
| 写入时被强制退出 | — | 无 | 已提交的数据完整，未提交的回滚（SQLite 保证） | 不测 |
| 系统时区或日期变化 | `NSCalendarDayChanged` | 无 | 按新的本地日期命名备份；同一天最多一份 | L1（跨日边界） |
| 同时运行多个实例 | — | 两个菜单栏图标 | SQLite 可以安全并发，但界面不同步 | 阶段 0 不处理（Issue #1） |

## 打开失败提示

- 使用 `NSAlert`，显示前先调用 `NSApp.activate()`。标题为"拾刻无法打开数据文件"；正文为原因文案和数据目录路径；按钮依次为"重试"（默认）、"打开数据目录"、"退出"。
- **重试：**重新走完整的 `open` 流程，成功后继续启动（04 §6.1）。
- **打开数据目录：**用 `NSWorkspace` 在访达中打开数据目录（不存在时打开上一级 `Application Support`），然后再次显示提示。
- **退出：**`NSApp.terminate(nil)`。
- 提示期间还没有创建菜单栏图标和 AppEnvironment，所以不会有半启动的状态。
- **模拟：**`-ShikeSimulateDatabaseOpenFailure YES` 只让第一次尝试抛出 `openFailed(.simulated)`，之后的"重试"走真实流程，以便验证恢复。原因文案为"模拟的错误（调试参数）"。

## 日志

每个失败都写日志：打开和写入写到 category `data`，备份写到 `backup`，提示展示写到 `ui`。记录错误分类和 SQLite 代码，不记录用户内容。
