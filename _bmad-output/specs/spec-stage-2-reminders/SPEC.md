> **确认方式：**本阶段规划由产品负责人在 2026-09-28 深夜预先授权（"规划好了之后直接去推进后续任务"），次日验收时一并追认；规划产物如有异议，按 06 §8"先判断哪一边错了"处理。

# 阶段 2 · 到点提醒（v0.2）

## Why

阶段 1 让"记下来"成立，但待办没有时间能力——"周五下午三点交报告"只能当一句纯文字存着，到点不会有人提醒，逾期的任务也不会自己浮上来。本阶段给待办装上时间：输入时顺带识别时间（docs/05 的解析引擎已在阶段 0 就绪），到点用系统通知提醒，通知上能直接完成或稍后提醒，退出拾刻通知照常送达；列表按逾期/今天/以后分组，菜单栏显示剩余计数。目标是"从记录到提醒走完全程"，并且全程遵守"用户可选"的产品原则（全天提醒时间、稍后时长、计数口径都可设置）。

## Capabilities

- **CAP-1** 时间识别与高亮（S2-01）
  - **intent:** 待办模式下边输入边按 docs/05 识别时间，识别文字在输入框内高亮，输入框下方给出结果提示；提示可一键取消本次识别；便签模式不识别。
  - **success:**
    - 输入"周五下午三点交报告"："周五下午三点"高亮，下方提示 `🕒 周五 15:00 提醒`；
    - 只有日期时提示"周六（全天）"；时间已过时红字"今天 09:00（已过）"；相对时长显示"今天 12:30 提醒（30 分钟后）"；
    - 点提示上的 ✕ 后提示变灰"不识别时间"，直到输入框被清空才恢复识别；
    - 切到便签模式不识别、不高亮、无提示；
    - 歧义规则（05 §6 A1～A4）在界面表现成立："有两点需要注意"不识别，"两点开会"识别（验收项）。
- **CAP-2** 提交与标题清理（S2-02）
  - **intent:** 提交时按 05 §7 从原文得到标题，时间信息进 `due` 而不留在标题里。
  - **success:** 验收项：回车后列表显示"交报告 · 周五 15:00"；05 §7 五步清理（含 Issue #2 的迭代修订，本次落盘）有 L1 用例覆盖；清理后为空则保留原文；识别被 ✕ 取消时提交的待办不带时间、标题即原文（只做空白与标点清理）。
- **CAP-3** 待办时间规则（S2-03）
  - **intent:** 什么时间提醒由明确的规则决定，全天待办可设置提醒时刻。
  - **success:** 提醒计划为 ShikeData 纯函数（04 §6.7）：候选=未删除未完成且有 due 的待办；提醒时间=snoozedUntil 优先，其次带时刻用 dueAt、全天用当天"全天待办提醒时间"；只保留晚于当前时刻的、按时间先后取前 50。全天提醒时刻偏好 `reminder.allDayMinutes`（默认 540 = 09:00）；已过去的照常保存为逾期、不发通知。全天提醒时间、稍后时长（`reminder.snoozeMinutes`，默认 10）在设置-提醒分页可改。
- **CAP-4** 到点通知（S2-04）
  - **intent:** 到点收到系统通知，通知上能完成或稍后提醒，点击能定位到该条；App 没运行也照常送达。
  - **success:**
    - 通知：标题=待办标题，正文=时间文案（"今天 15:00"/"全天 · 今天"），默认提示音；
    - 按钮"完成"与"稍后提醒（10 分钟）"（括号时长随 `reminder.snoozeMinutes` 变化）：完成调仓储置完成；稍后提醒写 `snoozedUntil`（此后按调度重排）；
    - 点通知本体：打开面板、切到待办模式、滚动定位并高亮 1.5 秒；
    - 拾刻在前台时同样显示横幅；提前排期的本地通知在 App 退出后照常送达（验收项：2 分钟后的待办，退出拾刻仍收到）。
- **CAP-5** 通知调度（S2-05）
  - **intent:** 系统中已排的通知始终与数据库一致。
  - **success:** 以待办 uuid 为通知标识对账：删掉计划中不存在或已变化的，补上缺少的；对账时机=启动、待办数据变化（合并 0.5 秒内多次变化）、跨天、唤醒（`NSWorkspace.didWakeNotification`）、提醒相关设置变化；只排最近 50 条；重复调用幂等（NFR20）。
- **CAP-6** 待办分组（S2-06）
  - **intent:** 待办按时间状态分组，过时的一眼可见。
  - **success:** 分组「逾期（红）」「今天」「以后」「无日期」「已完成（N）」（折叠，保持阶段 1 交互）；空组不显示；组内按时间先后（无日期按创建时间）；跨天与唤醒后自动重新分组（验收项：过午夜"今天"自动移"逾期"）；行样式 `○ 标题 · 时间`，时间显示按 03 §6（今年以内不显示年份、全天不显示时刻、逾期红色）。
- **CAP-7** 编辑时间（S2-07）
  - **intent:** 时间可以后补、修改和清除，不必重打整句。
  - **success:** 右键"设置时间…"弹层：日历选日期、"包含时刻"开关、时刻选择；快捷按钮今天、明天、下周一、清除时间；编辑标题不重新识别时间（03 §6）。
- **CAP-8** 菜单栏计数（S2-08）
  - **intent:** 菜单栏一眼看到还有多少事，口径可设置。
  - **success:** 偏好 `menuBar.counter`：不显示 / 逾期+今天（默认）/ 全部未完成；数字显示在图标右侧，为 0 时不显示；待办模式分段按钮上显示同样的数字角标；完成一条后立即减少（验收项）。
- **CAP-9** 搜索（S2-09）
  - **intent:** 记多了以后能找回来。
  - **success:** ⌘F 或点顶栏放大镜打开，搜索框替换输入框位置；范围=未删除的便签内容与待办标题（含已完成）；不区分大小写；停止输入 0.2 秒后自动搜索；结果分「便签」「待办」两组、匹配文字高亮；无结果显示"没有找到"××""与清除按钮；点击结果退出搜索、切模式、滚动定位并高亮；Esc 退出搜索（Esc 顺序更新为：结束编辑 → 退出搜索 → 收起面板）。
- **CAP-10** 通知权限（S2-10）
  - **intent:** 通知被系统或用户关掉时，用户要被告知"到点不会响"。
  - **success:** 第一次创建带时间的待办时请求通知权限；被拒后待办模式顶部显示黄色提示条"通知已关闭，到点不会提醒"与"打开系统设置"按钮（验收项）；设置-提醒分页显示权限状态与打开系统设置。

## Constraints

- **沿用阶段 0/1 全部硬约束：**模块边界与导入检查（CI checks）；ShikeKit 不引入 AppKit/SwiftUI/**UserNotifications**（提醒计划是 ShikeData 纯函数，通知框架只在 App 层）；无单例、依赖注入；错误只抛 `ShikeDataError`、不 `try?` 吞写入；文案键集中 xcstrings（`extractionState: manual`）；T0 基准；"警告即错误"只在 CI（ADR-019）；GPL 文件头；新文件先 `xcodegen generate`。
- **不新增迁移：**`todo` 表的 `dueAt`/`dueHasTime`/`snoozedUntil` 列在阶段 0 建表时已就位（data-layer.md），本阶段纯功能开发，无 schema 变更、无迁移前备份触发。
- **通知框架接缝：**App 层经协议封装 UNUserNotificationCenter（L2 注入内存替身，绝不真实请求权限或发通知）；授权状态以系统为准持久观察。
- **05 §7 修订（Issue #2）：**第 3、4 步改为重复执行直到结果不再变化；同一次提交内修改 05 规则、§9.13 用例与测试（06 §4.2）。
- **新偏好键：**`menuBar.counter`（默认 overdueAndToday）、`reminder.allDayMinutes`（默认 540）、`reminder.snoozeMinutes`（默认 10），集中 `Preferences.Key` 注册并同步 04 §5.5（04 §11.2 步骤）。
- **时间与口径：**全部日界、时刻计算经 `Options.timeZone` 的公历；"今天/逾期"分组以本地时区的当天为界；跨天事件用 `NSCalendarDayChanged`。
- **解析即服务：**界面只调用 `ChineseDateParser.parse(_:now:)` 与 `TitleCleaner`，注入 now 与时区，不改解析规则本身（docs/05 唯一权威）；误识别规则的界面行为回归到 05 §9.10/§9.12 用例。
- **验收基线：**通知、徽标、定位高亮等系统行为归 L3 人工验收；L1/L2 覆盖计划函数、对账逻辑、分组规则、搜索匹配、清理规则、界面状态机。

## Non-goals

- 阶段 3 及以后：桌面卡片（S3）、最近删除（S4-05）、首次启动引导（S4-08）、导出（S4）、完成动画与键盘导航（S5-01/02）、外观设置（S5-04）、便签待办互转（S5-03）。
- 全局快捷键"新建便签 / 新建待办"（S4-01）。
- 重复任务、农历、节假日（05 §8 暂不支持清单）。
- 单实例限制（Issue #1）；通知的富媒体/自定义声音；跨设备同步。
- 设置-卡片、数据分页的真实化（仍为占位）。
