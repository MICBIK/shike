**可复现步骤（本机手动，约 10 分钟，需 GUI 会话；workflow 版全自动在分支）：**

1. 建临时目录（`/tmp/sparkle-s4-00/{keys,serve,logs,Applications}`）；建 Swift 包：约 70 行 `main.swift`，SPM `.package(url: "https://github.com/sparkle-project/Sparkle.git", exact: "2.10.0")`；启动自记版本到日志 → 5 秒后 `checkForUpdates()` → 240 秒兜底自退；委托回调留痕全链节点（注意 2.10 更名：`didFinishLoading`、`SPUUserUpdateState`）。
2. 临时 EdDSA 密钥（不碰钥匙串）：Swift CryptoKit `Curve25519.Signing.PrivateKey()`，私钥 seed 的 base64 写 `keys/eddsa_priv.txt`（600）、公钥写 `eddsa_pub.txt`——与 Sparkle `generate_keys -x` 导出格式一致，`sign_update --ed-key-file` 直接接受。
3. 装配 .app：SPM release 产物 + Sparkle.framework 入 Frameworks；**`install_name_tool -add_rpath @executable_path/../Frameworks`（缺这步启动即 dyld 崩溃——SPM 产物只带构建布局 rpath）**；Info.plist 写 `SUFeedURL=http://127.0.0.1:8765/appcast.xml`、`SUPublicEDKey`、`SUEnableAutomaticChecks`/`SUScheduledCheckInterval=3600`/`SUAutomaticallyUpdate`、`NSAllowsLocalNetworking`（http 测试源需要，生产 https 免）；ad-hoc 由内向外签名：框架内 XPC（Installer/Downloader）与 Updater.app → 框架 → 宿主。
4. v2 发布物：`zip -qry`（保框架符号链接）→ `bin/sign_update --ed-key-file … -p`（工具在 SPM resolve 后的 `.build/artifacts/sparkle/Sparkle/bin/`，无需 brew）出 `sparkle:edSignature` + `length` → 写 appcast.xml；再重装 v1 到 Applications/。
5. `python3 -m http.server 8765` 托管；启动 v1；看 launch.log：`LAUNCHED 1.0 → APPCAST_LOADED → DID_FIND_VALID_UPDATE → WILL_INSTALL → TERMINATE 1.0 → LAUNCHED 2.0`（同一路径）；更新后 PlistBuddy=2.0、strict 签名校验过、无 quarantine、httpd 日志两条 GET 200。
6. 负向：`dd` 改 zip 第 1000 字节（appcast 签名与长度不动）→ 重复 4-5 → `ABORTED … Code=3002 "EdDSA signature does not match"`、bundle 保持 1.0。
7. 清理：杀 http.server 与 app，`rm -rf` 临时目录（密钥随目录销毁，全程未离开 /tmp）。
