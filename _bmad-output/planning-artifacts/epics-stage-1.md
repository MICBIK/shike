# 拾刻 Shike - Epic Breakdown（阶段 1）

## Overview

本文件把拾刻阶段 1（随手记）的需求拆成可以逐个实现的故事。需求来源（06 §8）：

| 通常的来源 | 拾刻的对应来源 |
|---|---|
| PRD | 阶段规格 `_bmad-output/specs/spec-stage-1-capture/SPEC.md` |
| 架构文档 | 规格伴随文件、阶段 0 规格（data-layer.md、app-shell.md）和 docs/04 |
| UX 文档 | docs/03 中与阶段 1 相关的章节（§2～§7、§9、§13、§14） |

阶段 1 是 Epic 2（阶段 N = Epic N+1，06 §8）。括号中的 CAP、S 编号用于追溯。FR 编号延续阶段 0 的史诗文件（FR38 起），NFR 延续 NFR15 起；阶段 0 的全部硬约束继续生效。

## Requirements Inventory

### Functional Requirements

**面板行为**

FR38：面板的 Esc 与尺寸（CAP-1、S1-01）：
- Esc 按顺序处理：结束编辑 → 收起面板（"退出搜索"层阶段 2 加入中间位置）；
- 右下角拖动把手调整尺寸，结束时保存到 `panel.size`，重开恢复；
- 尺寸钳制：最小 300×360、最大 600×1000，且不超出所在屏幕的可见区域；
- 连续快速点击图标不出现"刚关上又弹开"（阶段 0 的 10 毫秒防抖保持有效）。

FR39：全局快捷键（CAP-2、S1-02）：
- KeyboardShortcuts 注册名为 `togglePanel` 的快捷键，默认 ⌃⌥N，默认开启；按下呼出面板，再按收起；
- 设置-快捷键分页提供录制控件与开关，修改后立即生效，关闭后不再响应；
- 该分页从占位变为真实分页。

FR40：模式切换与呼出模式（CAP-3、S1-03）：
- 分段控件、输入框内 Tab、⌘1 / ⌘2 三种方式都切换「便签｜待办」；
- 呼出时进入哪个模式由 `panel.openMode` 决定：`last`（默认，用 `panel.lastMode`）/ `note` / `todo`；
- 任何切换都更新 `panel.lastMode`；切换时两份草稿各自保留。

FR41：快速输入框与提交（CAP-4、S1-04）：
- 输入法安全：`hasMarkedText()` 为真（拼音未上屏）时不替换文字、不提交，回车交给输入法；
- ⇧↩ 在便签模式插入换行，待办模式无作用；
- 高度从单行随内容增高，便签最多 6 行、待办最多 2 行，超出后框内滚动；
- 占位文案：便签「记点什么…（⇧↩ 换行）」、待办「要做什么？」；
- ↩（非组合态）提交：便签走 `NoteRepository.create(content:)`，待办走 `TodoRepository.create(title:due:)` 且 due 为 nil；成功后输入框清空、焦点保留，新条目出现在列表顶部并短暂高亮 1 秒；空内容（含全空白）提交无反应；
- 提交失败时输入保留，顶栏下方红色提示条"保存失败：原因"和"重试"（阶段 0 机制）；重试针对当时失败的那次输入，成功后清除提示条。

FR42：呼出即打字与草稿（CAP-5、S1-03、S1-04）：
- 从呼出到输入框获得焦点之间的可打印按键（含回车）被缓存，输入框就绪后按顺序回放，一个不丢；面板收起时丢弃缓冲；
- 打开面板时焦点在输入框；
- 草稿两种模式各一份：收起面板、切换模式都保留；退出拾刻时已持久化（`panel.draft.note`、`panel.draft.todo`），下次启动恢复。

FR43：便签列表与编辑（CAP-6、S1-05）：
- 分组：「置顶」（pinnedAt 非空，按置顶时间降序；空则不显示）、「便签」（updatedAt 降序，观察流已保证）；
- 列表行显示内容前 3 行（超出省略）和相对修改时间：刚刚 / N 分钟前 / 今天 HH:mm / 昨天 / M月d日；
- 单击行原位编辑；停止输入 0.5 秒后、失去焦点、收起面板时自动保存（`updateContent`）；Esc 或点击别处结束编辑；
- 行右键菜单：编辑、置顶 / 取消置顶、复制内容、删除。

FR44：待办列表与完成（CAP-7、S1-06）：
- 分组：「待办」（未完成，新建的在上）、「已完成（N）」（默认折叠，可展开；空组不显示）；
- 列表行：圆圈按钮 + 标题；
- 勾选立即划线变灰，1 秒后移入"已完成"组，这 1 秒内再点可以取消；勾回后回到"待办"组；
- 单击标题原位单行编辑（防抖同便签，走 `updateTitle`）；
- 行右键菜单：编辑、删除。

FR45：删除与撤销（CAP-8、S1-07）：
- 删除无需确认；删除后面板底部出现"已删除「内容前 12 个字…」"和"撤销"，停留 5 秒，连续删除时显示最近一条并重置计时；
- 面板内（非编辑状态）⌘Z 按删除的先后顺序逐条撤销；撤销调用 `restore`，便签恢复后内容和位置不变（ADR-017 的 updatedAt 语义）；
- 编辑时把内容清空后结束编辑，视为删除（走同一撤销通道）。

FR46：开机自启（CAP-9、S1-08）：
- 使用 `SMAppService.mainApp` 注册和注销；
- 右键菜单"开机自启"勾选项与设置-通用开关，两者状态一致；
- 每次都从系统读取状态；状态为"需要批准"时，设置-通用显示说明和"打开登录项设置"按钮（`openSystemSettingsLoginItems()`）。

FR47：右键菜单完整（CAP-9、S1-09）：菜单项依次为打开拾刻、分隔线、设置…（⌘,）、开机自启（勾选项）、关于拾刻、分隔线、退出拾刻（⌘Q）；"打开拾刻"打开面板。

FR48：空状态引导（CAP-10、S1-10）：便签空状态为图标 + "还没有便签" + "在上方输入，回车保存"；待办为图标 + "没有待办" + "输入要做的事，回车保存"。

**支撑需求**

FR49：新偏好键（跨故事，CAP-1/3/5）：`panel.size`（默认 360×520）、`panel.lastMode`（默认 note）、`panel.openMode`（默认 last）、`panel.draft.note`、`panel.draft.todo`（默认空）；集中在 `Preferences.Key`，默认值同处注册，并同步 04 §5.5。

FR50：新依赖与移植登记（跨故事）：
- 引入 KeyboardShortcuts（MIT，ADR-015），以精确版本锁定，登记 NOTICE；
- 五个移植文件（CaptureTextView、TypingBuffer、PopoverResizeHandle、HotkeyService、LaunchAtLoginService）按 06 §9 加来源与修改说明，登记 NOTICE 与 04 §7，去掉 EventKit、单例和已废弃 API。

### 非功能需求

NFR15：阶段 0 的全部硬约束继续生效（04、06 §12、ADR-013/015/017/019/020）：模块边界与导入检查、无单例、错误只抛 `ShikeDataError`、不 `try?` 吞写入、文案集中、T0 基准、"警告即错误"只在 CI、GPL 文件头。每个故事在"依据"中引用与它相关的部分。

NFR17：相对时间格式化是纯函数，注入 now 与时区，不读系统当前时间；用于列表行显示。

NFR18：删除撤销栈是会话级的界面状态，不持久化；面板收起不清空（5 秒提示条会消失，但 ⌘Z 仍可撤销本会话内的删除）。

NFR19：本阶段解决 deferred-work.md「面板提示条的重试生命周期」两条遗留（重试绑定当次失败输入；重试成功后清除提示条）。

## Epic List

### Epic 2: 阶段 1 · 随手记

完成后，产品负责人每天使用拾刻：
- ⌃⌥N 呼出面板，立即打字，回车保存——便签和待办 3 秒记下；
- 列表所见即所存：置顶、编辑、完成、删除、撤销全部可用；
- 草稿、面板尺寸、模式记忆让"随手"成立；开机自启让它常驻。

数据从本阶段起真实积累。本史诗对应 02 中的 S1-01～S1-10 和阶段 1 的 10 条验收。

**覆盖的功能需求：**FR38～FR50（全部）。NFR15～NFR19 分配到各故事的验收标准中。

**实施说明：**
- 依赖顺序：2-1（面板行为）先做——输入框和列表都依赖面板的尺寸与 Esc 框架；2-2（快捷键）与 2-1 并行无冲突。
- 2-3（模式）→ 2-4（输入框）→ 2-5（呼出即打字与草稿）是捕捉链路，顺序实现。
- 2-6、2-7（两类列表）依赖 2-4 的提交；2-8（删除撤销）依赖两者。
- 2-9（开机自启与右键菜单）、2-10（空状态引导）相对独立，可穿插。
- 每个故事按 bmad-build 的 oneshot 循环实现：实现 → L1/L2 测试 → checks → 独立盲审 → 台账 → 提交推送盯 CI。

## Epic 2 Stories

### Story 2.1: 面板行为——Esc 与尺寸记忆

作为每天使用拾刻的人，
我希望 Esc 能收起面板、拖动右下角能调整大小并被记住，
以便面板适应我的屏幕和习惯，且不会被误触发打断输入。

**依据：**FR38、FR49（panel.size）；NFR15；scope-boundaries.md「PopoverController」；app-shell.md「组件契约」中的 PopoverController、PopoverResizeHandle；03 §3、§13；04 §6.2、§11.2。

**验收标准：**

**假如** 面板打开且输入框正在编辑
**当** 按 Esc
**那么** 先结束编辑（回到非编辑状态），再次按 Esc 收起面板；收起时草稿保留

**假如** 面板打开且列表行处于编辑状态
**当** 按 Esc
**那么** 只结束该行编辑，面板不收起；再次按 Esc 才收起面板

**假如** 面板打开
**当** 拖动右下角把手调整尺寸
**那么** 尺寸实时跟随；小于 300×360 钳到最小，大于 600×1000 钳到最大，且任何时刻都不超出所在屏幕的可见区域；鼠标抬起时保存到 `panel.size`

**假如** 调整过尺寸
**当** 收起面板再打开，或退出拾刻重开
**那么** 面板以保存的尺寸出现

**假如** 面板以 360×520 默认尺寸首次运行
**当** 不做任何调整
**那么** `panel.size` 未写入时使用默认值；默认值在 `Preferences.Key` 注册

**假如** 面板刚收起
**当** 10 毫秒内再次点击图标
**那么** 面板不打开（阶段 0 防抖回归，L2 测试覆盖）

**假如** 实现本故事
**那么** 新增 `Shike/Panel/PopoverResizeHandle.swift`（移植，含 GPL 来源头）并登记 NOTICE 与 04 §7；尺寸钳制逻辑为纯函数并有 L1 测试

### Story 2.2: 全局快捷键

作为不用鼠标的人，
我希望随时按 ⌃⌥N 呼出或收起面板，并能改成自己的组合或关掉，
以便拾刻融入我的肌肉记忆。

**依据：**FR39、FR50（依赖与移植登记）；NFR15；ADR-015；scope-boundaries.md「HotkeyService」；app-shell.md「组件契约」中的 HotkeyService；03 §13；04 §3（KeyboardShortcuts）、§11.2。

**验收标准：**

**假如** 拾刻正在运行
**当** 按 ⌃⌥N
**那么** 面板打开；再按一次面板收起

**假如** 引入依赖
**当** 查看 Package.swift 与工程配置
**那么** KeyboardShortcuts 以精确版本锁定、登记 NOTICE；App 目标通过 HotkeyService 使用它，界面代码不直接引用库类型

**假如** 查看 `Shike/Services/HotkeyService.swift`
**那么** 它是从 demo `KeyboardShortcutService.swift` 移植的（GPL 来源头 + NOTICE + 04 §7 登记），去掉单例与旧逻辑；快捷键名为 `togglePanel`，默认组合 ⌃⌥N，默认开启

**假如** 打开设置-快捷键分页
**那么** 该分页不再是占位：有"呼出 / 收起面板"的录制控件（KeyboardShortcuts.Recorder）和启用开关；录制新组合后立即生效，关闭开关后快捷键不再响应，重新打开后恢复

**假如** 快捷键在呼出面板的同时按下
**当** 面板出现前就开始打字
**那么** 输入不会丢失（与 Story 2.5 的 TypingBuffer 衔接；本故事先保证按键事件入口统一走 HotkeyService → PopoverController.toggle）

**假如** HotkeyService 被组装
**当** 运行 L2 测试
**那么** 服务能用内存库 + 独立 UserDefaults 组装；封装逻辑（默认值、开关状态的读写）有测试；不在测试中真实注册全局快捷键

### Story 2.3: 模式切换与呼出模式

作为记录不同内容的人，
我希望用 Tab 或 ⌘1/⌘2 快速切换便签和待办，并决定呼出时进入哪个模式，
以便连续记录时不碰鼠标，呼出时总在我想用的模式。

**依据：**FR40、FR49（panel.lastMode/openMode）；NFR15；scope-boundaries.md「PanelModel」；app-shell.md「组件契约」中的 PanelModel（扩展）、SettingsView（扩展）；03 §3、§4、§9；04 §5.5、§11.2。

**验收标准：**

**假如** 面板处于便签模式
**当** 在输入框中按 Tab
**那么** 切换到待办模式；再按切回；⌘1 直达便签、⌘2 直达待办；分段控件点击同样生效

**假如** 切换模式
**当** 观察输入框
**那么** 输入框内容变成目标模式的草稿（两份草稿互不覆盖）；占位文案随模式变化；原模式的输入保留在原草稿中

**假如** 每次模式变化
**当** 查看偏好设置
**那么** `panel.lastMode` 更新为当前模式

**假如** `panel.openMode` 为 `last`（默认）
**当** 收起面板后再次呼出
**那么** 进入上次的模式

**假如** 在设置-通用中把"呼出时进入"改为"总是便签"或"总是待办"
**当** 收起后再呼出
**那么** 总是进入设定模式（呼出不改写 `panel.lastMode` 之外的状态）

**假如** 模式决策逻辑被实现
**当** 运行测试
**那么** 决策是纯函数（openMode × lastMode → 初始模式），L1 覆盖全部组合；五个新偏好键的默认值与读写有 L2 测试（若 2.1 尚未建立 panel.size，本故事一并补齐）

### Story 2.4: 快速输入框与提交

作为随手记录的人，
我希望在面板顶部直接打字、回车就保存，
以便记一条内容不需要任何多余动作，输了法也不会丢字。

**依据：**FR41、FR50（移植登记）；NFR15、NFR16、NFR19；scope-boundaries.md「CaptureTextView」「PanelModel」；app-shell.md「组件契约」中的 CaptureTextView、PanelModel（扩展）、文案表；03 §4、§14；04 §6.3、§11.7。

**验收标准：**

**假如** 面板打开
**当** 查看输入区
**那么** 顶栏下方是快速输入框，占位文案便签为「记点什么…（⇧↩ 换行）」、待办为「要做什么？」；输入框获得焦点，光标就位

**假如** 用拼音输入法输入，拼音尚未上屏
**当** 按回车
**那么** 只完成拼音上屏，不提交；上屏后的文字正常进入输入框；组合期间文字不被替换、不高亮刷新

**假如** 便签模式下输入多行
**当** 按 ⇧↩
**那么** 输入框内换行；高度随内容增高，最多 6 行，超出后框内滚动；待办模式按 ⇧↩ 无作用，最多 2 行

**假如** 输入"买牛奶"并回车
**当** 提交
**那么** 便签模式下创建一条内容为"买牛奶"的便签（`NoteRepository.create`）；输入框清空、焦点保留，可以立即输入下一条；列表顶部出现该条并高亮 1 秒；待办模式下同样创建标题为该文本的待办（due 为 nil）

**假如** 输入框为空或全是空白
**当** 按回车
**那么** 无任何反应（不创建、不清空、不报错）

**假如** 开启 `-ShikeSimulateWriteFailure YES` 后输入并回车
**当** 提交失败
**那么** 输入内容保留在输入框；顶栏下方出现红色"保存失败：模拟的错误（调试参数）"和"重试"；点"重试"后该次输入成功保存、提示条消失、输入框清空（NFR19：重试绑定当次输入）

**假如** 提交成功后立即收起面板
**当** 再次呼出
**那么** 输入框为空（草稿已随提交清空）

**假如** 实现本故事
**那么** `Shike/Panel/CaptureTextView.swift` 自 demo 移植（GPL 来源头、NOTICE、04 §7 登记；去掉自动补全等）；高度计算与组合态判断的可纯化部分有 L1/L2 测试；文案新增键入文案表

### Story 2.5: 呼出即打字与草稿

作为性子急的人，
我希望按下快捷键后立刻打字，面板出现之前敲的字一个不丢，
以便捕捉脑中一闪而过的念头；也希望没提交的内容在我回来时还在。

**依据：**FR42、FR49（panel.draft.*）；NFR15、NFR18；scope-boundaries.md「TypingBuffer」「PanelModel」；app-shell.md「组件契约」中的 TypingBuffer、PanelModel（草稿）；03 §3、§4；04 §6.2（按键缓冲）、§11.2。

**验收标准：**

**假如** 面板处于收起状态
**当** 按下 ⌃⌥N 后立即连续打字（面板尚未出现）
**那么** 所有可打印字符与回车都被缓存；面板出现、输入框就绪后按顺序回放——字符进入输入框，回车执行提交；一个不丢、顺序不乱

**假如** 缓存期间输入超过 200 字符
**当** 继续输入
**那么** 丢弃最早缓存的字符，保留最近 200 个

**假如** 面板收起
**当** 查看缓冲
**那么** 缓冲被丢弃（不跨呼出回放）

**假如** 输入"买牛奶"未提交
**当** 按 Esc 收起面板
**那么** "买牛奶"存入 `panel.draft.note`；再次呼出，输入框恢复"买牛奶"且光标在末尾；待办模式同理存 `panel.draft.todo`

**假如** 便签草稿"买牛奶"、待办草稿"交报告"
**当** 切换模式来回
**那么** 两份草稿互不干扰，各自在对应模式的输入框中出现

**假如** 有未提交草稿
**当** 退出拾刻再启动
**那么** 两份草稿按模式恢复（启动时从 `panel.draft.*` 读入）

**假如** 提交成功
**当** 查看草稿存储
**那么** 对应模式的草稿被清空

**假如** 实现本故事
**那么** `Shike/Panel/TypingBuffer.swift` 自 demo 移植改造（GPL 来源头、NOTICE、04 §7 登记）；缓冲/回放/上限逻辑有 L1 测试（事件注入抽象）；草稿读写与"收起不清空"有 L2 测试

### Story 2.6: 便签列表与编辑

作为使用拾刻的人，
我希望看到所有便签、单击就能改、能置顶和复制，
以便记录的内容可管理，重要的便签始终在列表上方。

**依据：**FR43、FR48（便签侧）；NFR15、NFR17；scope-boundaries.md「NoteListView」；app-shell.md「组件契约」中的 NoteListView、RelativeTimeFormatter、文案表；03 §5、§14、§15；data-layer.md「仓储」「观察」。

**验收标准：**

**假如** 存在便签若干（有置顶有普通）
**当** 打开面板的便签模式
**那么** 「置顶」组在前（按置顶时间降序），「便签」组在后（按最近修改降序）；组标题分别为"置顶""便签"；置顶组为空时不显示该组

**假如** 一条便签内容超过 3 行
**当** 查看列表行
**那么** 行内只显示前 3 行，超出省略；下方小字显示相对修改时间（刚刚 / N 分钟前 / 今天 14:20 / 昨天 / 9月20日，格式按 03 §5）

**假如** 单击某行
**当** 进入编辑
**那么** 该行原位变为编辑框，内容完整、光标就位；停止输入 0.5 秒后自动保存（`updateContent`）；点击别处或按 Esc 结束编辑；失去焦点、收起面板也触发保存

**假如** 编辑导致 updatedAt 变化
**当** 观察列表
**那么** 该便签按新修改时间重新排序（观察流推送后界面跟随）

**假如** 右键点击某行
**当** 菜单出现
**那么** 菜单项为：编辑、置顶 / 取消置顶（按当前状态显示其一）、复制内容、删除；"复制内容"把便签全文放入剪贴板；"置顶/取消置顶"调用 `setPinned`；"删除"走 Story 2.8 的删除通路（本故事先接软删除，无提示条）

**假如** 便签列表为空
**当** 查看空状态
**那么** 图标 + "还没有便签" + 引导句"在上方输入，回车保存"（本故事实现便签侧引导，见 FR48）

**假如** 实现本故事
**那么** 新增 `Shike/Panel/NoteListView.swift` 与 `Shike/Support/RelativeTimeFormatter.swift`；相对时间格式化有 L1 测试（注入 now，覆盖刚刚边界、跨天、跨月）；分组的展示逻辑有 L2 测试（内存库构造数据）

### Story 2.8: 删除与撤销

作为怕误删的人，
我希望删除不需要确认，但总能撤销，
以便快速清理而不怕手滑。

**依据：**FR45；NFR15、NFR18；scope-boundaries.md「撤销提示条」「PanelModel」；app-shell.md「组件契约」中的 UndoBar、PanelModel（撤销栈）；03 §7、§14；data-layer.md「仓储」（softDelete/restore、updatedAt 语义）。

**验收标准：**

**假如** 删除一条便签或待办（任意入口：右键菜单、编辑清空）
**当** 删除发生
**那么** 无确认弹窗，条目从列表消失（软删除）；面板底部浮出"已删除「内容前 12 个字…」"和"撤销"按钮

**假如** 撤销提示条正在显示
**当** 不做任何操作
**那么** 5 秒后提示条自动消失

**假如** 连续删除多条
**当** 每次删除
**那么** 提示条内容替换为最近删除的一条，计时重置

**假如** 提示条显示期间点"撤销"
**当** 撤销
**那么** 最近删除的一条恢复（`restore`），便签回到原来的排序位置、内容不变（ADR-017：删除不更新 updatedAt）；提示条消失或显示下一条

**假如** 面板处于非编辑状态
**当** 按 ⌘Z
**那么** 按删除的先后顺序逐条撤销（最近删的先恢复）；无可撤销删除时 ⌘Z 无反应；编辑状态中 ⌘Z 仍是文字撤销，不触发删除撤销

**假如** 编辑便签时清空全部内容
**当** 结束编辑（点别处、Esc 或收起面板）
**那么** 该便签被删除（软删除），走同一撤销通道可恢复

**假如** 撤销栈存在多条
**当** 收起面板再打开
**那么** 撤销能力保留（会话级，NFR18）；退出拾刻后栈清空（不持久化）

**假如** 实现本故事
**那么** 新增 `Shike/Panel/UndoBar.swift`；PanelModel 的删除栈与撤销有 L2 测试（内存库：删除→restore 回推→列表顺序不变）；2.6/2.7 的"删除"菜单项在本故事统一接入提示条通路
