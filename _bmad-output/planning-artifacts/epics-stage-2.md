## Requirements Inventory

### Functional Requirements

**时间识别与提交**

FR51：待办模式边输入边识别（CAP-1、S2-01）：每次非组合态文本变化调 `ChineseDateParser.parse`（注入 now/timeZone）；`matchedRanges` 在输入框内高亮；便签模式不识别。
FR52：识别提示条（CAP-1、S2-01）：输入框下方 `🕒 文案 ✕`；带时刻"周五 15:00 提醒"、仅日期"周六（全天）"、已过红字"今天 09:00（已过）"、相对时长"今天 12:30 提醒（30 分钟后）"。
FR53：取消识别（CAP-1、S2-01）：✕ 后变灰"不识别时间"且不再识别，直到输入框清空；草稿恢复（呼出/切模式）后重新解析。
FR54：标题清理（CAP-2、S2-02）：按修订后的 05 §7（第 3、4 步迭代到不动点，Issue #2）从原文得标题；清理后为空保留原文；取消识别的提交只做空白与标点清理、due 为 nil；提交失败输入与识别状态保留。
FR55：待办时间规则（CAP-3、S2-03）：`ReminderPlan` 纯函数——候选=未删除未完成有 due；fireDate=snoozedUntil 优先，其次带时刻用 dueAt、全天用当天 00:00+`reminder.allDayMinutes`；只保留晚于 now、升序前 50。
FR56：全天提醒时刻可设置（CAP-3、S2-03）：偏好 `reminder.allDayMinutes` 默认 540；设置-提醒分页修改后立即影响后续计划。
FR57：过去的时间照常保存（CAP-3、S2-03）：提交已过时刻不报错、不发通知，进入逾期分组。

**通知**

FR58：到点通知（CAP-4、S2-04）：本地通知标题=待办标题、正文=时间文案（"今天 15:00"/"全天 · 今天"）、默认声音；类别带"完成""稍后提醒（N 分钟）"两动作。
FR59：通知动作（CAP-4、S2-04）：完成→`setCompleted(true)`；稍后提醒→`snooze(until: now + reminder.snoozeMinutes)`（默认 10，可设 5/10/15/30/60）；snooze 后重排调度。
FR60：点击通知本体（CAP-4、S2-04）：打开面板、切待办模式、滚动定位并高亮 1.5 秒；拾刻在前台时同样显示横幅。
FR61：退出仍送达（CAP-4、S2-04）：通知提前排期（UNCalendar/TimeInterval 触发），App 未运行照常送达；动作随启动处理（等数据库就绪）。
FR62：调度对账（CAP-5、S2-05）：以待办 uuid 为通知标识与系统已排通知对账（删多余/变化、补缺少）；时机=启动、待办变化（0.5s 合并）、跨天、唤醒、提醒设置变化。
FR63：只排最近 50 条（CAP-5、S2-05）。

**列表与计数**

FR64：待办五分组（CAP-6、S2-06）：逾期（红）/今天/以后/无日期/已完成（折叠）；空组不显示；组内逾期/今天/以后按 due 升序、无日期按创建降序、已完成按完成时间降序；行样式 `○ 标题 · 时间`。
FR65：时间显示与重排（CAP-6、S2-06）：今天 15:00 / 明天 / 周五 15:00 / 9月30日 / 2027年3月5日 15:00，今年内不显示年份、全天无时刻、逾期红；跨天（NSCalendarDayChanged）与唤醒后重新分组。
FR66：编辑时间（CAP-7、S2-07）：右键"设置时间…"弹层：日历选日期、"包含时刻"开关、时刻选择；快捷按钮今天、明天、下周一、清除时间；调 `TodoRepository.setDue`。
FR67：编辑标题不重新识别时间（CAP-7、S2-07）。
FR68：菜单栏计数（CAP-8、S2-08）：`menuBar.counter` = 不显示 / 逾期+今天（默认）/ 全部未完成；图标右侧数字，0 不显示。
FR69：待办模式角标（CAP-8、S2-08）：分段控件"待办"上显示同样数字。

**搜索与权限**

FR70：搜索打开与范围（CAP-9、S2-09）：⌘F 或顶栏放大镜；搜索框替换输入框位置；范围=未删除便签内容与待办标题（含已完成）；不区分大小写；0.2 秒防抖。
FR71：搜索结果与导航（CAP-9、S2-09）：分「便签」「待办」两组（按 updatedAt 降序）；匹配文字高亮；点击退出搜索、切模式、滚动定位、高亮；无结果"没有找到"××""+清除；Esc 退出搜索（Esc 顺序：结束编辑 → 退出搜索 → 收起面板）；搜索态不进草稿、不识别、呼出即打字关闭。
FR72：权限请求时机（CAP-10、S2-10）：第一次创建带时间待办时请求通知权限。
FR73：被拒提示（CAP-10、S2-10）：待办模式顶部黄色提示条"通知已关闭，到点不会提醒" + "打开系统设置"；设置-提醒分页显示权限状态与入口。

**设置与偏好**

FR74：新偏好键（跨故事，CAP-3/8）：`menuBar.counter`（overdueAndToday）、`reminder.allDayMinutes`（540）、`reminder.snoozeMinutes`（10）；集中 `Preferences.Key` 注册，同步 04 §5.5；设置-提醒分页真实化（全天提醒时间、稍后时长、权限状态），设置-通用新增菜单栏计数。

## Epic List

### Epic 3: 阶段 2 · 到点提醒

完成后，"周五下午三点交报告"从一句话变成一次提醒：
- 输入时时间被认出来并提示，回车后标题干净、时间入账；
- 到点系统通知，上面一键完成或稍后提醒，退出拾刻也照响；
- 逾期/今天/以后分组让欠账可见，菜单栏数字随时提醒；
- 记多了能搜索找回。

本史诗对应 02 中的 S2-01～S2-10 和阶段 2 的 9 条验收。

**覆盖的功能需求：**FR51～FR75（全部）。NFR20～NFR23 分配到各故事的验收标准中。

**实施说明：**
- 依赖顺序：3-1（识别高亮）→ 3-2（标题清理）是输入链路；3-3（时间规则）是通知链路的地基；3-4（到点通知）→ 3-5（调度）→ 3-10（权限）是通知链路；3-6（分组）→ 3-7（编辑时间）是列表链路；3-8（计数）、3-9（搜索）相对独立，靠后穿插。
- 05 §7 修订（Issue #2）在 3-2 的提交内完成：规则、用例、测试同一提交。
- 每个故事按 bmad-build 的 oneshot 循环实现：实现 → L1/L2 测试 → checks → 独立盲审 → 台账 → 提交推送盯 CI。

## Epic 3 Stories

### Story 3.1: 时间识别与高亮

作为记录待办的人，
我希望输入"周五下午三点交报告"时时间被认出来并提示我，
以便确认拾刻理解对了再保存。

**依据：**FR51～FR53、FR75（草稿恢复后重解析）；NFR21/22；stage-2-components.md §1；docs/05 §6、§9.10、§9.12；docs/03 §4。

**验收标准：**

1. 待办模式输入"周五下午三点交报告"："周五下午三点"在输入框内高亮，下方提示"🕒 周五 15:00 提醒 ✕"。
2. 输入"周六交报告"提示"周六（全天）"；输入"今天 09:00 开会"（已过）提示红字"今天 09:00（已过）"；输入"30分钟后喝水"提示"今天 12:30 提醒（30 分钟后）"样式。
3. 输入"有两点需要注意"不识别不高亮；输入"两点开会"识别（05 §6 规则在界面成立）。
4. 点 ✕：提示变灰"不识别时间"，高亮消失；继续输入不再识别；清空输入框后恢复识别。
5. 切到便签模式：不识别、不高亮、无提示；切回待办模式恢复。
6. 组合态（拼音未上屏）不解析、不刷新高亮；草稿恢复时立即解析一次。
7. 提示文案全部走 xcstrings；解析注入 now/timeZone（L2 固定时区断言）。

### Story 3.2: 提交与标题清理

作为记录待办的人，
我希望回车后标题里不留"周五下午三点"这类时间文字，
以便列表干净、时间进了该去的地方。

**依据：**FR54；NFR21；stage-2-components.md §2；docs/05 §7、§9.13；GitHub Issue #2；docs/06 §4.2（规格同步）。

**验收标准：**

1. 验收项：输入"周五下午三点交报告"回车，列表显示"交报告 · 周五 15:00"（标题经 05 §7 清理，时间入 due）。
2. 05 §7 修订落地：第 3、4 步迭代到不动点；"明天交报告提醒我。"→"交报告"；新增 docs/05 §9.13 用例与 L1 测试（同一次提交，关闭 Issue #2）。
3. 清理后为空（输入全是时间词）→ 标题保留原文（去首尾空白）。
4. 取消识别（✕）后提交：待办无时间，标题只做空白与标点清理。
5. 提交失败（-ShikeSimulateWriteFailure）：输入、识别状态、高亮全部保留；重试成功后按正常路径清空。
6. 连续记录语义不变：成功后清空输入框、焦点保留、复位识别状态。

### Story 3.3: 待办时间规则

作为依赖提醒的人，
我希望全天待办在设定时刻提醒、过期任务不吵我，
以便提醒符合预期。

**依据：**FR55～FR57、FR56（偏好）；NFR20/22；stage-2-components.md §3；docs/04 §6.7、§5.5；docs/03 §9。

**验收标准：**

1. ShikeData 新增 `ReminderPlan.plan(todos:now:timeZone:allDayMinutes:limit:)` 纯函数：候选过滤、snoozedUntil 优先、全天换算、只留未来、升序前 50，全部有 L1 用例（含恰为 now、snooze 已过、第 50/51 条边界）。
2. 全天待办"周六交报告"（allDayMinutes=540）计划在周六 09:00；跨时区注入测试成立（NFR22）。
3. 过去时刻提交成功且不进计划（验收项的 L1 部分）。
4. 新偏好键 `reminder.allDayMinutes`（默认 540）、`reminder.snoozeMinutes`（默认 10）、`menuBar.counter`（默认 overdueAndToday）注册并同步 04 §5.5；设置-提醒分页真实化（全天提醒时间、稍后时长），修改后 L2 断言写入偏好。
5. 本故事不接通知框架（纯函数 + 偏好 + 设置页）。

### Story 3.4: 到点通知

作为依赖提醒的人，
我希望到点收到通知，上面能直接完成或稍后提醒，
以便不用打开拾刻也能处理到期的事。

**依据：**FR58～FR61、FR72；NFR23；stage-2-components.md §3/§4；docs/03 §11；docs/04 §6.7。

**验收标准：**

1. `NotificationScheduling` 协议封装 UNUserNotificationCenter（pending/add/remove/授权），L2 内存替身；ShikeKit 零 UserNotifications（NFR23）。
2. 通知内容：标题=待办标题、正文=时间文案（"今天 15:00"/"全天 · 今天"）、默认声音、类别 `reminder`（动作：完成 / 稍后提醒（N 分钟））；L2 断言内容与触发时刻。
3. 通知动作：完成→仓储 setCompleted(true)；稍后提醒→`snooze(until: now + snoozeMinutes)`，数据流触发重排；点击本体→回调打开面板、切待办、定位 uuid 并高亮 1.5 秒（回调注入，L2 验证调用）。
4. 前台横幅：代理实现"前台也展示"（L2 断言代理设置）。
5. 权限请求：首次提交带时间待办时经闭包请求（L2 验证"仅带时间触发"）；退出仍送达靠提前排期（触发时刻 > now 的 UNTimeInterval/Calendar 触发器，L1/L2 断言），真实送达归 L3。
6. 冷启动处理动作前等待数据库就绪（代码路径存在并有注释说明）。

### Story 3.5: 通知调度

作为依赖提醒的人，
我希望系统中排着的通知永远和我的数据一致，
以便改时间、完成、删除后不会收到过时的提醒。

**依据：**FR62～FR63；NFR20/21/23；stage-2-components.md §3；docs/04 §6.7。

**验收标准：**

1. `ReminderScheduler.reconcile()`：以待办 uuid 为标识对账——删除计划外/已变化的、补缺少的；L2 用内存替身覆盖：新增、改时间（旧删新加）、完成（删）、删除（删）、snooze（改时间）、无变化（零操作，幂等 NFR20）。
2. 触发时机接线：启动后、待办流变化（0.5 秒合并）、`NSCalendarDayChanged`、`NSWorkspace.didWakeNotification`、提醒偏好变化；L2 用注入的触发源验证（不真等系统事件）。
3. 只排前 50 条（与 ReminderPlan 一致，超出的不进系统）。
4. 对账失败（权限拒绝时 add 失败）不崩溃、写日志；授权后下次对账自动补上。

### Story 3.6: 待办分组

作为欠了很多事的人，
我希望逾期、今天、以后、无日期分得清清楚楚，
以便先还最久的债。

**依据：**FR64～FR65；NFR22；stage-2-components.md §5；docs/03 §6、§14。

**验收标准：**

1. 分组纯函数（注入 now/timeZone）：逾期（due<今天0点、红）/今天/以后/无日期/已完成（默认折叠，保持阶段 1 折叠交互）；空组不显示；组内排序按契约。
2. 行样式 `○ 标题 · 时间`：今天 15:00 / 明天 / 周五 15:00 / 9月30日 / 2027年3月5日 15:00；今年内不显示年份、全天不显示时刻、逾期红色（格式化纯函数注入 now/timeZone，L2 用例表）。
3. 跨天重排：`NSCalendarDayChanged` 后"今天"移"逾期"（验收项的 L2 部分：注入新 now 断言分组变化）；唤醒同理。
4. 已完成组仍按完成时间降序、1 秒延迟入组交互保持；无日期组保持"新条目在顶部"。
5. 空状态文案阶段 2 起追加"可以直接写时间，比如'明天下午三点'"（03 §14）。

### Story 3.7: 编辑时间

作为记录待办的人，
我希望右键就能改时间或清除时间，
以便计划变了不用重打整句。

**依据：**FR66～FR67；NFR22；stage-2-components.md §5；docs/03 §6。

**验收标准：**

1. 待办右键菜单新增"设置时间…"；弹层含日历（DatePicker）、"包含时刻"开关、时刻选择、快捷按钮今天 / 明天 / 下周一 / 清除时间。
2. 确认后 `setDue` 写库（全天=当天 00:00、带时刻=所选时刻）；清除时间=due 置 nil；L2 注入仓储替身断言。
3. 单击标题原位编辑不重新识别时间（编辑路径与识别无关，L2 回归）。
4. 编辑失败提示复用保存失败提示条语义（保留旧值，显示红色提示）。
5. "下周一"按 docs/05 顺延规则的口径计算（注入 now/timeZone 的纯函数 + L1 用例）。

### Story 3.8: 菜单栏计数

作为菜单栏的重度用户，
我希望图标旁边直接看到还剩多少事，
以便不打开面板也知道负担。

**依据：**FR68～FR69、FR74；NFR22；stage-2-components.md §6；docs/03 §2、§9。

**验收标准：**

1. 三种口径（none / overdueAndToday / allIncomplete）为纯函数（注入 now/timeZone），L1 用例覆盖口径边界（已完成不算、逾期算今天外、0 为 0）。
2. 状态项图标右侧显示数字；0 不显示；数据变化/跨天/唤醒即时更新（L2 注入待办流断言更新调用）。
3. 设置-通用新增"菜单栏计数"三选项，切换立即生效（L2 断言偏好写入与重算）。
4. 待办模式分段控件"待办"上显示同样数字角标（0 不显示）。
5. 验收项"完成一条后立即减少"的 L2 部分：完成动作后计数重算被调用。

### Story 3.9: 搜索

作为记了很多东西的人，
我希望按 ⌘F 输入关键词就能找到便签和待办，
以便找回来不需要翻列表。

**依据：**FR70～FR71、FR75；NFR21；stage-2-components.md §7；docs/03 §8、§13、§14。

**验收标准：**

1. ⌘F 或顶栏放大镜进入搜索：搜索框替换输入框位置（焦点自动就位）；Esc 顺序更新为结束编辑 → 退出搜索 → 收起面板（PopoverController escapeOutcome 扩展）。
2. 匹配：未删除便签内容 + 待办标题（含已完成）、不区分大小写 contains；0.2 秒防抖（L2 注入时钟或用 waitUntil 轮询）。
3. 结果分「便签」「待办」两组（updatedAt 降序）、匹配子串高亮（UTF-16 区间，L2 断言区间）；无结果显示"没有找到"××"" + 清除按钮。
4. 点击结果：退出搜索、切对应模式、ScrollViewReader 滚动定位、高亮 1.5 秒（L2 验证状态迁移）。
5. 搜索态：输入不写草稿、不触发时间识别、TypingBuffer 不截获（呼出即打字在搜索态让位，L2 回归）。

### Story 3.10: 通知权限

作为被系统关掉通知的用户，
我希望拾刻告诉我"到点不会提醒"并给我入口，
以便不会以为提醒还在而误事。

**依据：**FR72～FR73、FR74；NFR23；stage-2-components.md §4；docs/03 §11、§14、§9。

**验收标准：**

1. 授权状态机（notDetermined / granted / denied）经协议观察；denied 时待办模式顶部黄色提示条"通知已关闭，到点不会提醒" + "打开系统设置"按钮（验收项 L2 部分：状态注入断言提示条出现/消失）。
2. "打开系统设置"打开通知设置面板（URL 常量注入，L2 断言调用）。
3. 设置-提醒分页显示当前权限状态 + 打开系统设置（granted/notDetermined/denied 三态文案）。
4. notDetermined 时首次提交带时间待办触发请求（与 3.4 衔接回归）；授权成功后提示条消失、调度自动补排（与 3.5 衔接）。
5. 便签模式不显示该提示条。
