# TZMemo 项目章程

> 文档编号：00 ｜ 状态：生效中 ｜ 上次更新：2026-09-23

## 1. 产品愿景

**一款 macOS 菜单栏便笺应用：随手呼出、秒级记录。** 便签可钉在桌面悬浮显示；便签与待办分离，待办支持中文自然语言日期与本地提醒。先做单机 Mac 版，验证后扩展 iOS / Windows / Android。

一句话对标：把 [demo 项目 Reminders MenuBar] 的"3 秒捕捉"体验，从提醒事项迁移到便笺领域。

## 2. 目标用户与核心场景

| 画像 | 场景 | 核心诉求 |
|---|---|---|
| 电脑前的工作者（首要） | 开会中突然有想法/待办，不想切走当前窗口 | 全局快捷键呼出 → 打字 → 回车，全程 ≤3 秒 |
| 多线任务的执行者 | 一堆琐碎待办需要"记下来再说"，但需要到点提醒 | 中文输入日期（"周五下午三点交报告"）即建提醒 |
| 桌面布置爱好者 | 重要事项希望一直看得见 | 便签钉在桌面悬浮显示 |

## 3. 产品目标与成功指标（1.0）

| 目标 | 衡量方式 |
|---|---|
| 捕捉体验达标 | 从呼出到记录完成 ≤3 秒（自测计时） |
| 自用留存 | 开发者本人连续日用 ≥30 天 |
| 小范围口碑 | 朋友分发后 ≥10 人安装且 ≥5 人周活（GitHub Issues/微信反馈收集） |
| 质量底线 | 解析引擎回归 100% 通过；无数据丢失类 Bug |

## 4. 范围

**v1.0（MVP，迭代 M1–M5）包含：** 菜单栏常驻 + 弹出面板、全局快捷键、双模式快速输入、便签/待办 CRUD、中文日期解析、本地提醒通知、搜索、钉便签悬浮卡片、Sparkle 更新、GitHub 分发。

**明确不做（当前阶段）：** 账号系统、云同步、iOS/Windows/Android 版、富文本/Markdown 渲染、协作分享。

**远期路线（按用户反馈排序）：** iOS（Swift 复用）→ Windows/Android（Flutter 双栈）→ 同步 + 账号体系。

## 5. 角色与协作流程（确认制）

| 角色 | 担当 |
|---|---|
| 产品负责人 / 验收人 | 用户（baihaibin） |
| 开发 / 文档 | AI 助手（ZCode） |

**迭代流程（每个里程碑循环一次）：**

```
① 计划：AI 产出该迭代的任务清单 + 设计方案（涉及界面时附 UX 设计章节）
② 确认：用户评审通过后才动工  ←←← 铁律，不得跳过
③ 实现：AI 编码 + 自测（单元测试 + 解析器回归）
④ 验收：用户按验收清单实测，AI 修复问题
⑤ 回顾：记录到迭代计划的回顾表，沉淀改进
```

## 6. Definition of Ready（任务可开工的条件）

- 任务在迭代计划中有明确描述与验收标准；
- 涉及新界面的，UX 设计文档已有对应章节；
- 涉及技术方案的，架构文档已有对应章节或 ADR。

## 7. Definition of Done（任务可验收的条件）

- 代码通过编译并按验收标准实测通过；
- 新增解析规则附带回归断言；数据层操作附带单元测试；
- 涉及的文档（PRD 状态列、迭代计划、README）已同步更新；
- `swift run parser-check` 全绿。
