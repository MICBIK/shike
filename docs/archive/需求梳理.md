## 一、产品定位（一句话）

**一款 macOS 菜单栏便笺应用：随手呼出、秒级记录，便签可钉在桌面悬浮显示；便签与待办分离，待办支持中文自然语言日期与本地提醒。先做单机 Mac 版，验证后扩展 iOS / Windows / Android。**

## 二、平台策略与长期架构（双栈路线）

| 阶段 | 平台 | 技术栈 | 说明 |
|---|---|---|---|
| 现在 | **macOS** | **Swift/SwiftUI + AppKit** | 产品的灵魂形态（菜单栏弹出面板）所在平台，体验优先 |
| 验证后 | iOS / iPadOS | Swift/SwiftUI | **复用 Mac 版业务逻辑**（模型、解析器、同步客户端），SwiftUI 界面大部分共享 |
| 验证后 | Windows + Android | Flutter（届时再复核） | 独立第二套 UI；中文解析规则表移植为 Dart；共享同一同步后端 |

依据：
1. **品类先例**：知名 Mac 菜单栏便签/速记应用（Tot、Antinote、SideNotes、Dropover、Anybox、MenubarX）**全部是原生 Swift，无一例外**；跨平台便签产品（Microsoft Sticky Notes、Notezilla 等）则普遍没有好用的 Mac 版。「Mac 上好用的便签全是原生单品」。
2. **Flutter 做此形态是劣势项**（调研评级 B-）：Flutter 没有 NSPopover 等价物，要做出「点击外部收起」的成熟面板**必须写 Swift 胶水代码**（NSStatusItem + NSPopover 承载 FlutterEngine）——等于 Dart 和 Swift 都要学；关键插件停滞（auto_updater 23 个月未更、launch_at_startup 18 个月、hotkey_manager 约 2 年）；毛玻璃效果随 Flutter 升级反复损坏；包体 40-80MB、内存 100-200MB（约原生 2 倍，对常驻应用是硬伤）；**找不到任何知名的 Flutter 菜单栏应用**。
3. **Tauri 2 桌面端成熟**（托盘锚定 + 失焦收起有成熟模式、官方 updater 支持 GitHub latest.json、3-10MB 极轻），案例 pot-app/Cap/Clop——但仅当你本身是 Web 前端背景时作为替代选项，且 Android 端更新/自启等能力缺口仍在。
4. 双栈（苹果系 Swift + 其余 Flutter）是独立开发者社区的常见务实路线；中文解析引擎先做**语言无关的规则表 + 测试用例**，Swift 实现后可低成本移植 Dart。

## 三、macOS 版技术方案

- **语言/框架**：Swift 6 + SwiftUI，界面之外的关键处用 AppKit（与 demo 相同的组合）。
- **菜单栏面板**：`NSStatusItem` + `NSPopover`（demo 同款架构；SwiftUI 的 MenuBarExtra 不支持可拖拽调整大小的面板，高级面板的成熟做法就是回退 NSStatusItem + NSPanel）。面板行为对齐 demo：transient（点外部收起）、可拖拽调尺寸并记忆、透明毛玻璃背景（系统材质，免费获得）。
- **钉便签悬浮卡片**：`NSPanel`（无边框、非激活面板 `.nonactivatingPanel`、置顶 level、可拖动多实例）。
- **全局快捷键**：Carbon `RegisterEventHotKey` 或现代封装（如 KeyboardShortcuts 库，Sindre Sorhus 出品，MIT）。
- **数据**：本地 **SQLite + GRDB**，schema 预埋同步字段（`uuid` 主键、`updated_at`、`deleted` 软删除），读写收敛到 Repository 协议。
- **提醒**：`UNUserNotificationCenter` 本地通知，不依赖 EventKit。
- **中文日期解析**：Swift 纯函数模块 + 单元测试；**先定义规则表与测试用例（语言无关资产），便于日后移植 Dart**。首版范围：今天/明天/后天/大后天、周X/下周X、X天(周)后、X点[半/刻]/X点X分、早上/上午/中午/下午/晚上、X月X号、组合式（明早八点、周五下午三点、下个月3号）；不做农历/节日/模糊语（预留扩展位）。
- **开机自启**：`SMAppService`（现代 API，无需第三方）。
- **更新**：Sparkle 2 + EdDSA 自签名（**不需要开发者账号**），appcast.xml 放 GitHub Pages/Releases。
- **分发**：GitHub Releases + 朋友分发；未签名应用首次打开需右键打开或 `xattr -cr`，写入 README 安装说明。

## 四、数据模型（便签 / 待办分离，与 v2 一致）

```
Note（便签）
  id, uuid, content, color?, pinned, created_at, updated_at, deleted

Todo（待办）
  id, uuid, title, detail?, done, done_at?,
  due_at?, remind_at?, priority?, repeat_rule?,
  list_or_tag?, created_at, updated_at, deleted
```

- 快速输入栏双模式（便签｜待办），中文日期解析仅在待办模式生效，命中部分在输入框内**高亮**。
- 完成待办带动画。

## 五、多端同步（远期）与用户体系

- 同步后端：跨平台 BaaS（LeanCloud 国内访问好 / Supabase）或自建轻后端；不做 CloudKit（非苹果单平台、无开发者账号）。同步策略首版按字段 Last-Write-Wins。
- 账号体系随同步一起落地（「用户管理体系」的最终归宿）。
- **MVP 明确不做账号**；若实际需求是「本机多档案」，可后续加轻量档案切换，成本低。
- Windows/Android 版启动时，同步与账号已是现成能力，两栈共用同一后端。

### 当前进展（2026-09-23）

**已完成：**
- 中文日期解析引擎 `Packages/TZMemoDateParser`：独立 Swift 包、零依赖、纯函数规则引擎；回归测试器 `swift run parser-check` **144 条断言全部通过**（CLT 即可运行，无需 Xcode）。覆盖：相对日、X天后、周X（含下周/下下周/星期/礼拜变体）、月日（年份滚动）、下个月X号、时段+时刻组合、裸时刻口语推断。关键实现细节：时刻匹配前将日期命中区**遮蔽为等长占位符**，防止数字贪婪跨界（「周五三点」曾被匹配成「五三点」）。
- App 工程骨架：XcodeGen 工程配置 + App 源码（`TZMemoApp` / `AppDelegate` / `Note`+`Todo` 模型 / `AppDatabase` 迁移 / `MemoStore` 数据入口 / `ContentView` 双模式冒烟界面，已接入解析引擎预览）+ 单元测试 + README。全部源码通过 `swiftc -parse` 语法检查，`xcodegen generate` 已生成 `TZMemo.xcodeproj`。

**阻塞项（需要用户操作）：**
- 本机未安装 **Xcode**（仅有 Command Line Tools）。请从 App Store 安装 Xcode 并首次打开同意许可，然后在项目根目录执行：
  ```bash
  xcodegen generate   # 工程配置变更后需重新生成（xcodegen 已装好）
  open TZMemo.xcodeproj
  # Cmd+R 运行 M1 冒烟界面；Cmd+U 跑单元测试
  ```
- 首次构建时 Xcode 会拉取 GRDB（SPM 远程依赖），需要网络。

## 附录一：对「Windows 弹层体验」调研结论的回应

Windows 没有系统级 Popover 等价物，托盘弹层需手写（窗口锚定托盘位置 + 失焦隐藏），但有成熟模式与先例（PowerToys、Everything、OneDrive、Tauri positioner 插件）。结论：**Windows 版可行但确实要自己打磨，体验上限低于 macOS**——因此推迟、由 Mac 版先行是正确决策，而非放弃。
