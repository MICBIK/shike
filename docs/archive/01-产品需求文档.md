# TZMemo 产品需求文档（PRD）

> 文档编号：01 ｜ 状态：评审中（用户故事待产品负责人逐条确认）｜ 上次更新：2026-09-23
> 优先级定义：P0 = MVP 必须；P1 = 1.0 前应有；P2 = 验证后规划

## 1. Epic 与用户故事

### E1 快速捕捉（产品灵魂，全 P0）

**US-101** 作为工作者，我要通过菜单栏图标呼出面板，以便不离开当前工作记录想法。
- [ ] 点击菜单栏图标弹出面板，再点击收起
- [ ] 点击面板外部任意位置自动收起（transient）
- [ ] 面板出现时焦点已在输入框
- [ ] 无 Dock 图标、无主窗口（LSUIElement）

**US-102** 作为工作者，我要用全局快捷键呼出/收起面板，以便全程不碰鼠标。
- [ ] 默认快捷键可一键切换面板显隐
- [ ] 快捷键可在设置中自定义
- [ ] 呼出耗时无感（<300ms）

**US-103** 作为用户，我要在输入框回车即完成记录，以便零学习成本。
- [ ] 回车提交，输入框清空并保持焦点，可连续记录
- [ ] 空输入回车无副作用

**US-104** 作为用户，我要通过菜单栏图标了解未完成数量，以便不打开面板也心中有数。
- [ ] 图标显示未完成待办数，可切换为纯图标模式

### E2 便签管理

**US-201** 作为用户，我要新建/编辑/删除便签，以便管理随手记的内容。（P0）
- [ ] 删除需确认或可撤销（防误删，方案待定 → 评审项）

**US-202** 作为用户，我要置顶重要便签。（P1）
**US-203** 作为用户，我要给便签分标签/分组。（P1）
**US-204** 作为用户，我要搜索便签内容。（P0）
**US-205** 作为用户，我要给便签换颜色。（P2）

### E3 待办管理与提醒

**US-301** 作为用户，我要用一句中文创建带提醒的待办：「周五下午三点交报告」，以便不打断思路。（P0）
- [ ] 输入时解析出的日期在输入框内**原位高亮**
- [ ] 提交后待办携带提醒时间，命中文本从标题中剥离
- [ ] 解析范围见 [03-技术架构设计](03-技术架构设计.md) §6（解析引擎已实现）

**US-302** 作为用户，我要在到期时收到系统通知。（P0）
- [ ] 基于本地通知，App 未在前台也能送达
- [ ] 通知权限被拒绝时，界面内给出可见的到期提示（降级方案）

**US-303** 作为用户，我要勾选完成待办，并有完成的爽感。（P0：功能；P1：动画）
**US-304** 作为用户，我要设置待办优先级与重复规则。（P2）
**US-305** 作为用户，我要编辑/删除待办。（P0）

### E4 桌面钉便签

**US-401** 作为用户，我要把便签钉在桌面上常驻显示，以便重要信息始终可见。（P0 功能，M3 交付）
- [ ] 无边框悬浮卡片，可拖动位置、可置顶
- [ ] 可多实例、可从卡片关闭/取消钉住
- [ ] 不抢焦点（点击便签不激活当前应用切换）

### E5 设置与个性化

**US-501** 我要开机自启开关。（P0）
**US-502** 我要设置深浅色跟随系统、面板背景透明度。（P1）
**US-503** 我要设置排序方式（创建时间/到期时间/置顶优先）。（P1）
**US-504** 我要查看关于页并手动检查更新。（P0，M5）

### E6 分发与更新

**US-601** 作为朋友/用户，我要从 GitHub 下载安装，遇到 Gatekeeper 拦截有说明可查。（P0，M5）
**US-602** 作为用户，应用要能自动检查更新并升级（含国内镜像）。（P0，M5）
**US-603** 作为 Android 用户，我要应用内检查新版本并下载 APK。（P2，远期）

### E7 多端同步与账号（远期，全部 P2）

**US-701** 多设备同步便签/待办（BaaS 或自建，按字段 LWW）。
**US-702** 账号体系随同步落地。⚠️ 待产品负责人确认「用户管理体系」的最终含义（见需求梳理遗留问题 Q2）。

## 2. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 <1s；面板呼出 <300ms；常驻内存目标 <80MB；列表 1000 条不卡 |
| 可靠性 | 数据本地 SQLite，任何崩溃不丢已提交数据 |
| 隐私 | 无遥测、无账号、数据不出本机（同步功能上线前） |
| 兼容 | macOS 13+ |
| 可用性 | 核心流程（呼出→记录）≤3 秒；键盘可完成全部高频操作 |
| 可维护性 | 解析规则改动必须带回归断言；数据访问只经 MemoStore |
