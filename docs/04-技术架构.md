**依赖规则**

- App 依赖 ShikeData 和 ShikeDateParser；ShikeData 与 ShikeDateParser 互不依赖。
- 界面代码不直接访问数据库，只通过 ShikeData 的仓储和观察接口。
- ShikeData 和 ShikeDateParser 不依赖 AppKit、SwiftUI，可以在命令行用 `swift test` 测试。
- AppKit、通知中心、Sparkle 等系统集成只出现在 App 目标中。

## 4. 模块职责

### 4.1 ShikeDateParser

- `ChineseDateParser`：`init(timeZone: TimeZone = .current)`，内部固定使用公历、周一为一周之首，与系统的区域和日历设置无关。`parse(_ text: String, now: Date) -> DateParseResult?`。
- `DateParseResult`：`date`（目标时间；全天时为当天 00:00）、`hasTime`（是否确定到时刻）、`matchedRanges`（UTF-16 区间，按位置排序且互不重叠，可直接用于高亮）。
- 标题清理：根据识别结果从原文中去掉时间文字，规则见 [05 §7](05-中文日期解析规格.md#7-标题清理)。
- 实现要求：值类型、符合 `Sendable`，正则表达式预编译为静态常量，没有可变状态。
- 规则与用例以 [05-中文日期解析规格](05-中文日期解析规格.md) 为准。

### 4.2 ShikeData

本节为阶段 0 实现验证过的契约；完整的结构细节与测试清单见阶段 0 规格 `data-layer.md`（两处不一致时，以实现和测试为准并同步本文）。

- **AppDatabase：**`public final class AppDatabase: Sendable`。
  - `Options`：`timeZone`（全天规范化与备份命名）、`clock: @Sendable () -> Date`（经 GRDB 的 `transactionClock` 注入，同一事务内的时间戳相同，测试结果确定）、`simulateWriteFailure`（对应 `-ShikeSimulateWriteFailure`）。
  - `static func open(directory:options:)` 同步执行、启动时需要立即知道成败；`static func inMemory(options:)` 用 `DatabaseQueue` 执行同样的迁移，供测试和预览使用；`static let fileName = "shike.sqlite"`。
  - `open` 依次执行，任何一步失败都抛出 `openFailed(原因)`，不会创建替代库：①校验 `directory` 是绝对路径的文件 URL → ②创建目录 → ③以 `DatabasePool`（WAL）打开 → ④`hasBeenSuperseded` 检查（库来自更新的版本则失败，不写入）→ ⑤库中已有迁移且又有待执行的迁移时先做迁移前备份（§6.6）→ ⑥在事务中执行迁移。
- **记录类型：**公开模型在 `Domain/`，是 `Sendable` 值类型（`Note`、`NoteListItem`、`Todo`、`TodoDue`、`StickyCard`、`CardFrame`、`StickyCardOptions`、`VisibleCard`），主键为包内类型 `Note.ID`/`Todo.ID`（包装 `Int64`）。内部 Record 在 `Records/`，负责与数据库的编解码（ADR-020）：公开类型不能遵循从 `internal import` 引入的协议，uuid 的小写文本编码由 Record 的**静态函数** `databaseUUIDEncodingStrategy(for:)` 实现——误写成静态属性会被 GRDB 静默忽略，退回 16 字节 BLOB（ADR-006 记录的旧缺陷，有 `typeof(uuid) = 'text'` 测试兜底）。
- **仓储：**`NoteRepository`、`TodoRepository`、`StickyCardRepository` 都是 `Sendable` 结构体，`init(database:)` 创建。写方法一律 `async throws`、只抛 `ShikeDataError`：新建、修改、置顶、软删除、恢复、永久删除；待办的完成与取消完成、设置时间、稍后提醒；卡片的钉出、修改位置与选项、取消钉住。`create` 与 `pin` 返回模型（`pin` 在便签已钉出时返回现有卡片、不做改动），其余写方法不返回值；对不存在的记录抛出 `notFound`。各方法对 `updatedAt` 的影响按 ADR-017 执行。`simulateWriteFailure` 开启时，所有写方法不访问数据库直接抛 `writeFailed(.simulated)`；迁移、观察和备份不受影响。
- **数据观察：**基于 GRDB 的 `ValueObservation`，返回 `AsyncThrowingStream<[元素], any Error>`：`NoteRepository.observeActive()`（未删除的便签，附带"是否已钉到桌面"，按 updatedAt 降序）、`TodoRepository.observeActive()`（未删除的待办，按 createdAt 降序）、`StickyCardRepository.observeVisible()`（所属便签未删除的卡片及其便签，按 createdAt 升序）。订阅后先推送当前值，之后每次提交且影响到相关表时推送，重复值被去掉；取消消费的 `Task` 即停止观察。实现补充（GRDB 7.11 实测）：池观察感知不到其他连接的提交；被观察的表被删除后观察会静默挂起，因此桥接层把"活跃观察结束"一律视为读取通道断开，以 `readFailed(.ioError)` 结束流。
- **错误分类：**`ShikeDataError`：`notFound` / `openFailed` / `readFailed` / `writeFailed` / `backupFailed`，后四者携带 `DataFailureReason`（`diskFull`、`readOnly`、`permissionDenied`、`corrupted`、`busy`、`newerSchema`、`ioError`、`constraintViolation`、`invalidLocation`、`simulated`、`unknown(code:)`），按 SQLite 主结果码分类。App 端由 `ErrorText` 映射为中文文案，并以 `classification`（"类别/原因"）写入日志（分类用 `.public`，其余信息保持默认隐私级别）。
- **领域逻辑（纯函数）：**待办分组（逾期/今天/以后/无日期/已完成）、提醒计划（见 §6.7）、搜索关键字转义。
- **备份：**`backupIfNeeded(to:keep:) async throws -> BackupOutcome`，细节见 §6.6。

## 5. 数据模型 v1

### 5.1 约定

- `id` 是本地自增整数主键；`uuid` 是稳定标识，用于通知、卡片恢复和导出，以小写文本存储。
- 时间字段使用 GRDB 的默认存储格式（UTC 文本）。
- 删除一律为软删除（写入 `deletedAt`）；只有清理"最近删除"时才永久删除。
- `updatedAt` 表示内容最近一次被修改的时间（即列表中显示的"修改时间"）。以下变化时更新：便签的内容；待办的标题、时间、完成状态和稍后提醒；卡片的任何字段。软删除、恢复，以及便签的置顶和取消置顶，都不更新（ADR-017）。
- 迁移只追加：已发布的迁移永不修改，结构变更一律写新的迁移。新迁移按 `v2`、`v3`…… 命名（迁移器由内部工厂创建，生产代码只注册正式迁移，测试可注入测试专用迁移）；每个迁移配两类测试：空库迁移到最新版本，以及上一版本的库迁移到最新版本（以上一版本迁移生成的库作为夹具）。

## 6. 关键方案

### 6.1 应用生命周期与主菜单

- `main.swift` 创建 `NSApplication` 并设置 `AppDelegate`，不使用 SwiftUI 的 `App`/`Scene`。
- Info.plist 设置 `LSUIElement = YES`：没有 Dock 图标，菜单栏上也不显示应用菜单。
- **必须创建一个不显示的主菜单：**应用菜单（设置… ⌘,、退出 ⌘Q）和编辑菜单（撤销、重做、剪切、复制、粘贴、全选）。AppKit 生命周期下没有默认菜单，缺少编辑菜单时，输入框中的 ⌘C、⌘V、⌘Z 都不起作用。编辑菜单的撤销/重做选择器在 Swift 6 下不能用字符串构造（`Selector("undo:")` 编译失败），须定义 `@objc` 协议重命名方法后 `#selector` 引用；剪切/复制/粘贴/全选直接引用 `NSText` 的既有选择器。
- **启动顺序（阶段 0 已实现，其余按阶段追加）：**测试宿主检测（`SHIKE_TEST_HOST=1` 直接返回）→ 读调试参数（`LaunchOptions`）→ 确定数据目录（默认目录或 `-ShikeDataDirectory`，无效判"打不开"）→ 打开数据库，失败则进入 §6.6 的提示循环（重试成功后继续，不重启应用）→ 组装 AppEnvironment → 建立主菜单 → 创建设置窗口控制器与右键菜单 → 创建菜单栏图标和面板 → `panelModel.start()` 订阅观察 → `backupService.start()` 后台检查备份 → 提醒对账（阶段 2）→ 恢复卡片（阶段 3）→ 检查更新（阶段 4）。`applicationWillTerminate` 中停止面板、观察消费与备份服务。

### 6.2 菜单栏与面板（移植）

- `NSStatusItem` 加 `NSPopover`：`behavior = .transient`，`animates = false`。
- 左键开关面板；右键临时挂上菜单并弹出，弹出后再卸下。
- **防"刚关又开"：**记录面板关闭的时间；如果点击发生在关闭后 10 毫秒内，就不再打开。
- **外部点击兜底：**面板显示期间安装全局和本地鼠标按下监听，点在面板和图标之外就关闭面板（SwiftUI 菜单有时会破坏系统自带的点击外部收起）。
- **显示时：**激活应用，让面板窗口成为关键窗口，并聚焦输入框。
- **尺寸：**限制在所在屏幕的可见区域内；拖动结束时保存。
- **按键缓冲：**从呼出到输入框获得焦点之间，用本地按键监听把可打印的按键缓存起来，输入框就绪后按顺序回放。
- **Esc：**本地按键监听按"结束编辑 → 退出搜索 → 收起面板"的顺序处理。

### 6.3 快速输入框（移植）

- 用 `NSViewRepresentable` 包装 `NSScrollView` 中的 `NSTextView`，自绘占位文字。
- **输入法安全：**`hasMarkedText()` 为真（拼音未上屏）时，不替换文字、不刷新高亮属性；在 `doCommandBy` 中收到回车时，若处于组合状态则交给输入法，否则才提交。
- **高亮：**把解析得到的 UTF-16 区间直接设为强调色，只改颜色属性，不改动文字、选区和撤销记录。
- 高度随内容变化，达到最大行数后在框内滚动。
- 每次文字变化（且不在组合状态时）调用一次解析器；解析器单次耗时须低于 1 毫秒。

### 6.4 全局快捷键

- 通过 KeyboardShortcuts 注册名为 `togglePanel` 的快捷键，默认 ⌥N（2026-09-29 由 ⌃⌥N 改两键，存量安装启动时一次性迁移），按下时开关面板；设置中提供录制控件。
- 注册失败（比如被其他应用占用）时，在设置的快捷键分页中提示。

### 6.5 数据访问与界面同步

- 所有写操作通过仓储完成（`try await writer.write { … }`）。
- 界面模型（`@Observable`、`@MainActor`）订阅 `ValueObservation`；面板、桌面卡片和菜单栏计数都来自同一个数据库，天然保持一致，不需要手动刷新。

### 6.6 错误处理与数据安全

- **启动时数据库打不开：**弹出 `NSAlert`，按钮为"重试""打开数据目录""退出"。调试启动参数 `-ShikeSimulateDatabaseOpenFailure YES` 会让第一次打开失败，用于测试；之后点"重试"会走真实的打开流程（提示循环中"退出"调用 `NSApplication.terminate`，"打开数据目录"在访达中打开数据目录）。
- **错误分类与文案：**仓储抛出的 `ShikeDataError` 按 §4.2 的原因分类；`ErrorText` 把每个原因映射为文案表的中文文案，同时以 `Log.data` 记录"类别/原因"（分类用 `.public`）。不走降级路径：不改用内存库，不用空数据或默认值覆盖用户数据（ADR-013）。
- **迁移前备份：**打开已有的数据库、并且有待执行的迁移时，先在 `Backups/` 中生成 `shike-before-<迁移标识>-YYYY-MM-DD.sqlite`。这类文件不参与每日轮换，也不会被自动删除；同一天、同一迁移已有备份时不重复生成。备份失败时不执行迁移，`open` 抛出 `openFailed(备份失败的原因)`，按"打不开"处理（ADR-018）。新建的空库不做这种备份。
- **写入失败：**仓储抛出错误；`PanelModel` 捕获后显示红色提示条，并保留输入内容；同时写入日志。
- **每日备份（已实现）：**启动时和跨天时（`NSCalendarDayChanged`），若当天还没有备份，就在后台用 GRDB 的在线备份接口生成 `Backups/shike-YYYY-MM-DD.sqlite`。文件名中的日期由公历和 `Options.timeZone` 算出（en_US_POSIX 格式化，与系统区域无关）。实现要点：在线备份会把源库的 WAL 页头复制进目标文件，因此成功后要对目标库执行 `PRAGMA journal_mode=DELETE`，并清理目标路径残留的 `-wal`/`-shm`/`-journal` 侧车文件，备份才是可独立打开的单个 SQLite 文件；写入先落临时文件 `.shike-….partial` 再原子改名。失败时删除临时文件、只写日志不打断用户（阶段 4 起在设置中显示）。
- **备份轮换：**只处理文件名符合 `^shike-\d{4}-\d{2}-\d{2}\.sqlite$` 的文件，按文件名中的日期保留最新的 `keep` 份（至少 1），删除其余的；`shike-before-*` 和其他文件不动。
- **数据目录：**`~/Library/Application Support/Shike/`（应用不启用沙盒）。
- **调试参数：**定义在 `Shike/App/LaunchOptions.swift`，登记在 [06 §11](06-开发规范.md#11-调试)；`-Flag 值` 与 `-Flag=值` 两种写法都支持，只有旗标没有值时判为无效，绝不静默回退默认值。
  - `-ShikeSimulateWriteFailure YES`：让所有写操作失败，用于验收"保存失败时保留输入"。
  - `-ShikeDataDirectory <路径>`：把数据目录（包括 `Backups/`）换到指定的绝对路径（支持 `~` 展开）。路径无效时按"打不开"处理（原因 `invalidLocation`），不会退回默认目录。

### 6.7 提醒调度（阶段 2）

- **提醒计划（ShikeData 领域逻辑，纯函数）：**
  - 候选：未删除、未完成、有 `dueAt` 的待办。
  - 提醒时间：有 `snoozedUntil` 时用它；否则带时刻的用 `dueAt`，全天的用当天的"全天待办提醒时间"。
  - 只保留晚于当前时刻的，按时间先后取前 50 条。
- **调度器（App）：**以待办 uuid 作为通知标识，对比系统中已排的通知：删掉计划中不存在的或已变化的，补上缺少的。
  - 对账时机：启动、待办数据变化（合并 0.5 秒内的多次变化）、跨天（`NSCalendarDayChanged`）、唤醒（`NSWorkspace.didWakeNotification`）、提醒相关设置变化。
- **通知按钮：**注册通知类别，包含"完成""稍后提醒"两个动作。通知代理在前台也显示横幅；按"完成"调用仓储完成待办；按"稍后提醒"写入 `snoozedUntil`；点击通知本体则打开面板并定位该条。
- **权限：**第一次创建带时间的待办时请求；持续观察授权状态，用于显示提示条（S2-10）。

## 8. 并发模型

- 使用 Swift 6 严格并发检查；不启用"默认 MainActor 隔离"构建设置，界面类型、控制器和 `@Observable` 模型都**显式**标注 `@MainActor`，使 App 与 ShikeKit 的规则一致。
- 界面模型在自己持有的 `Task` 中用 `for try await` 消费观察流；停止或释放时取消该 `Task`（面板模型把任务存为 `@ObservationIgnored nonisolated(unsafe)` 属性，以便在释放路径取消）。
- 仓储是符合 `Sendable` 的结构体，内部使用 GRDB 的异步读写；ShikeKit 的公开类型都是 `Sendable` 值类型。
- 解析器是值类型、没有可变状态；预编译正则用 `static let` 存 `NSRegularExpression`——Swift `Regex` 不是 `Sendable`，作为静态常量在 Swift 6 下编译失败（已实测）。
- 系统回调（通知代理、NSEvent 监听等）先切到主线程，再访问界面状态；只有在确定回调位于主线程时（如指定 `queue: .main` 的通知）才用 `MainActor.assumeIsolated`。

4. 结果与失败写日志（category 取 `app`/`data`/`backup`/`ui` 之一）。示例：`BackupService`（`start()` 后台备份一次并订阅跨天通知；`backupNow()` 不抛出、结果只入日志）。

### 11.6 新增调试参数

1. 在 `Shike/App/LaunchOptions.swift` 定义 `-Shike<名称>`，同时支持 `-Flag 值` 和 `-Flag=值` 两种写法；只有旗标没有值时判为无效，不静默回退。
2. 在 `project.yml` 的 scheme 中预置该参数，默认不勾选；在 [06 §11](06-开发规范.md#11-调试) 登记。
3. 在 `ShikeTests/LaunchOptionsTests.swift` 加解析测试。示例：`-ShikeDataDirectory`（无效路径 → `invalidLocation`，绝不退回默认目录）。

### 11.7 移植 demo 文件
