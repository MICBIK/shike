## 1. 总体结构

```
┌─ App 目标：Shike（AppKit 管生命周期和窗口，SwiftUI 画界面）────────────┐
│ MenuBar   菜单栏图标、面板、右键菜单                                     │
│ Panel     面板内容：模式切换、快速输入框、列表、搜索、提示条              │
│ Cards     桌面卡片：窗口管理、自动隐藏                                   │
│ Settings  设置窗口                                                     │
│ Services  偏好设置、快捷键、开机自启、提醒调度、备份、更新                 │
├─ 本地 Swift 包：ShikeKit ──────────────────────────────────────────────┤
│ ShikeData        数据库、迁移、记录类型、仓储、领域逻辑、数据观察          │
│ ShikeDateParser  中文日期解析（只依赖 Foundation）                       │
└────────────────────────────────────────────────────────────────────────┘
```

**依赖规则**

- App 依赖 ShikeData 和 ShikeDateParser；ShikeData 与 ShikeDateParser 互不依赖。
- 界面代码不直接访问数据库，只通过 ShikeData 的仓储和观察接口。
- ShikeData 和 ShikeDateParser 不依赖 AppKit、SwiftUI，可以在命令行用 `swift test` 测试。
- AppKit、通知中心、Sparkle 等系统集成只出现在 App 目标中。

## 4. 模块职责

### 4.1 ShikeDateParser

- `ChineseDateParser`：`init(timeZone: TimeZone = .current)`，内部固定使用公历、周一为一周之首，与系统的区域和日历设置无关。`parse(_ text: String, now: Date) -> DateParseResult?`。
- `DateParseResult`：`date`（目标时间；全天时为当天 00:00）、`hasTime`（是否确定到时刻）、`matchedRanges`（UTF-16 区间，按位置排序且互不重叠，可直接用于高亮）。
- 标题清理：根据识别结果从原文中去掉时间文字，规则见 [05 §7](05-中文日期解析规格.md#7-标题清理)。
- 实现要求：值类型、符合 `Sendable`，正则表达式预编译为静态常量，没有可变状态。
- 规则与用例以 [05-中文日期解析规格](05-中文日期解析规格.md) 为准。

### 4.2 ShikeData

- **AppDatabase：**在 `~/Library/Application Support/Shike/shike.sqlite` 打开 `DatabasePool`（WAL 模式）并执行迁移；测试使用内存数据库。
- **记录类型：**`Note`、`Todo`、`StickyCard`，UUID 以小写文本存储。
- **仓储：**`NoteRepository`、`TodoRepository`、`StickyCardRepository`。所有方法 `async throws`，包括新建、修改、置顶、软删除、恢复、永久删除；待办的完成与取消完成、设置时间、稍后提醒；卡片的钉出、修改位置与选项、取消钉住。
- **数据观察：**基于 GRDB 的 `ValueObservation`，提供未删除的便签（附带"是否已钉到桌面"）、未删除的待办、菜单栏计数、已钉卡片及其便签内容等查询流。
- **领域逻辑（纯函数）：**待办分组（逾期/今天/以后/无日期/已完成）、提醒计划（见 §6.7）、搜索关键字转义。
- **备份：**把数据库备份到指定文件，并按日期清理旧备份。

## 5. 数据模型 v1

### 5.1 约定

- `id` 是本地自增整数主键；`uuid` 是稳定标识，用于通知、卡片恢复和导出，以小写文本存储。
- 时间字段使用 GRDB 的默认存储格式（UTC 文本）。
- 删除一律为软删除（写入 `deletedAt`）；只有清理"最近删除"时才永久删除。
- `updatedAt` 表示内容最近一次被修改的时间（即列表中显示的"修改时间"）。以下变化时更新：便签的内容；待办的标题、时间、完成状态和稍后提醒；卡片的任何字段。软删除、恢复，以及便签的置顶和取消置顶，都不更新（ADR-017）。
- 迁移只追加：已发布的迁移永不修改，结构变更一律写新的迁移。

### 5.2 表 `note`（便签）

| 列 | 类型 | 约束 | 说明 |

| id | INTEGER | 主键，自增 | |

| updatedAt | DATETIME | 非空 | |

### 5.3 表 `todo`（待办）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|

## 6. 关键方案

### 6.1 应用生命周期与主菜单

- `main.swift` 创建 `NSApplication` 并设置 `AppDelegate`，不使用 SwiftUI 的 `App`/`Scene`。
- Info.plist 设置 `LSUIElement = YES`：没有 Dock 图标，菜单栏上也不显示应用菜单。
- **必须创建一个不显示的主菜单：**应用菜单（设置… ⌘,、退出 ⌘Q）和编辑菜单（撤销、重做、剪切、复制、粘贴、全选）。AppKit 生命周期下没有默认菜单，缺少编辑菜单时，输入框中的 ⌘C、⌘V、⌘Z 都不起作用。
- **启动顺序：**打开数据库（失败则进入 §6.6 的错误流程）→ 组装 AppEnvironment → 建立主菜单和菜单栏图标 → 后台检查备份 → 提醒对账（阶段 2）→ 恢复卡片（阶段 3）→ 检查更新（阶段 4）。

### 6.2 菜单栏与面板（移植）

- `NSStatusItem` 加 `NSPopover`：`behavior = .transient`，`animates = false`。
- 左键开关面板；右键临时挂上菜单并弹出，弹出后再卸下。
- **防"刚关又开"：**记录面板关闭的时间；如果点击发生在关闭后 10 毫秒内，就不再打开。
- **外部点击兜底：**面板显示期间安装全局和本地鼠标按下监听，点在面板和图标之外就关闭面板（SwiftUI 菜单有时会破坏系统自带的点击外部收起）。
- **显示时：**激活应用，让面板窗口成为关键窗口，并聚焦输入框。
- **尺寸：**限制在所在屏幕的可见区域内；拖动结束时保存。
- **按键缓冲：**从呼出到输入框获得焦点之间，用本地按键监听把可打印的按键缓存起来，输入框就绪后按顺序回放。
- **Esc：**本地按键监听按"结束编辑 → 退出搜索 → 收起面板"的顺序处理。

### 6.3 快速输入框（移植）

- 用 `NSViewRepresentable` 包装 `NSScrollView` 中的 `NSTextView`，自绘占位文字。
- **输入法安全：**`hasMarkedText()` 为真（拼音未上屏）时，不替换文字、不刷新高亮属性；在 `doCommandBy` 中收到回车时，若处于组合状态则交给输入法，否则才提交。
- **高亮：**把解析得到的 UTF-16 区间直接设为强调色，只改颜色属性，不改动文字、选区和撤销记录。
- 高度随内容变化，达到最大行数后在框内滚动。
- 每次文字变化（且不在组合状态时）调用一次解析器；解析器单次耗时须低于 1 毫秒。

### 6.4 全局快捷键

- 通过 KeyboardShortcuts 注册名为 `togglePanel` 的快捷键，默认 ⌃⌥N，按下时开关面板；设置中提供录制控件。
- 注册失败（比如被其他应用占用）时，在设置的快捷键分页中提示。

### 6.5 数据访问与界面同步

- 所有写操作通过仓储完成（`try await writer.write { … }`）。
- 界面模型（`@Observable`、`@MainActor`）订阅 `ValueObservation`；面板、桌面卡片和菜单栏计数都来自同一个数据库，天然保持一致，不需要手动刷新。

### 6.6 错误处理与数据安全

- **启动时数据库打不开：**弹出 `NSAlert`，按钮为"重试""打开数据目录""退出"。调试启动参数 `-ShikeSimulateDatabaseOpenFailure YES` 会让第一次打开失败，用于测试；之后点"重试"会走真实的打开流程。
- **迁移前备份：**打开已有的数据库、并且有待执行的迁移时，先在 `Backups/` 中生成 `shike-before-<迁移标识>-YYYY-MM-DD.sqlite`。这类文件不参与每日轮换。备份失败时不执行迁移，按"打不开"处理（ADR-018）。
- **写入失败：**仓储抛出错误；`PanelModel` 捕获后显示红色提示条，并保留输入内容；同时写入日志。
- **自动备份：**启动时和跨天时，若当天还没有备份，就在后台用 GRDB 的备份接口生成 `Backups/shike-YYYY-MM-DD.sqlite`，然后删除超出保留份数（默认 7）的最旧备份。备份失败只写日志，不打断用户；阶段 4 起在设置中显示。
- **数据目录：**`~/Library/Application Support/Shike/`（应用不启用沙盒）。
- **调试参数：**
  - `-ShikeSimulateWriteFailure YES`：让所有写操作失败，用于验收"保存失败时保留输入"。
  - `-ShikeDataDirectory <路径>`：把数据目录（包括 `Backups/`）换到指定的绝对路径。路径无效时按"打不开"处理，不会退回默认目录。

### 6.7 提醒调度（阶段 2）

- **提醒计划（ShikeData 领域逻辑，纯函数）：**
  - 候选：未删除、未完成、有 `dueAt` 的待办。
  - 提醒时间：有 `snoozedUntil` 时用它；否则带时刻的用 `dueAt`，全天的用当天的"全天待办提醒时间"。
  - 只保留晚于当前时刻的，按时间先后取前 50 条。
- **调度器（App）：**以待办 uuid 作为通知标识，对比系统中已排的通知：删掉计划中不存在的或已变化的，补上缺少的。
  - 对账时机：启动、待办数据变化（合并 0.5 秒内的多次变化）、跨天（`NSCalendarDayChanged`）、唤醒（`NSWorkspace.didWakeNotification`）、提醒相关设置变化。
- **通知按钮：**注册通知类别，包含"完成""稍后提醒"两个动作。通知代理在前台也显示横幅；按"完成"调用仓储完成待办；按"稍后提醒"写入 `snoozedUntil`；点击通知本体则打开面板并定位该条。
- **权限：**第一次创建带时间的待办时请求；持续观察授权状态，用于显示提示条（S2-10）。

### 6.8 桌面卡片（阶段 3）

- **管理：**`StickyCardManager` 订阅"已钉卡片 + 未删除便签"的查询，按便签 uuid 创建、更新或关闭窗口。
- **窗口：**`StickyCardPanel` 继承 `NSPanel`：
  - `styleMask` 为 `[.borderless, .nonactivatingPanel, .resizable]`，背景透明，圆角由 SwiftUI 内容绘制。
  - `canBecomeKey` 返回 true，以便编辑；`becomesKeyOnlyIfNeeded = true`；`hidesOnDeactivate = false`。
- **层级：**`floating` 对应 `.floating`；`normal` 对应 `.normal`；`desktop` 对应"桌面图标层 + 1"（`CGWindowLevelForKey(.desktopIconWindow) + 1`），以 S3-00 的验证结果为准。
- **空间：**所有空间时加 `.canJoinAllSpaces`；显示在全屏应用之上时加 `.fullScreenAuxiliary`；桌面层额外加 `.stationary`。
- **自动隐藏：**
  - 至少有一张卡片开启自动隐藏时，才安装全局和本地的鼠标移动监听（`.mouseMoved`、`.leftMouseDragged`）。
  - 按 [03 §10.4](03-交互设计.md#104-自动隐藏) 的状态机切换：隐藏时 `alphaValue` 设为隐藏不透明度、`ignoresMouseEvents = true`；浮现时恢复 1 和 false。
  - 监听鼠标移动不需要辅助功能权限（只有按键事件需要），由 S3-00 最终确认。
- **持久化：**移动或调整大小结束 0.3 秒后保存位置。
- **屏幕变化：**收到 `NSApplication.didChangeScreenParametersNotification` 后，若某张卡片与所有屏幕的可见区域都不相交，就把它移到主屏并依次错开。
- **编辑：**卡片中用 SwiftUI `TextEditor`；双击切换为可编辑；停止输入 0.5 秒后通过仓储保存。

### 6.9 设置窗口

- `SettingsWindowController` 持有一个普通 `NSWindow`，用 `NSHostingController` 承载 SwiftUI 的设置视图，全局只有一个实例。
- 打开时调用 `NSApp.activate()` 和 `makeKeyAndOrderFront`。
- 不使用 SwiftUI 的 `Settings` 场景，因此不需要 demo 中那 218 行绕路代码。

### 6.10 开机自启

使用 `SMAppService.mainApp` 注册和注销；每次都从系统读取状态；状态为"需要批准"时，引导用户打开系统设置的登录项页面。

### 6.11 自动更新与发布（阶段 4）

- Sparkle 2 的 `SPUStandardUpdaterController`；`SUFeedURL` 为 `https://micbik.github.io/shike/appcast.xml`，`SUPublicEDKey` 写在 Info.plist 中；EdDSA 私钥只保存在开发者的钥匙串中，绝不进仓库。
- 签名方式：ad-hoc 签名；不启用 Hardened Runtime 和 App Sandbox（ADR-011）。
- 发布脚本：`scripts/release.sh`（S4-03）。
- 整条链路在 S4-00 中验证。

### 6.12 隐私

没有遥测，不收集任何使用数据。唯一的网络访问是阶段 4 起的更新检查（只下载 appcast 和更新包）。日志只写在本机。

## 8. 并发模型

- 使用 Swift 6 严格并发检查。
- 界面、控制器和 `@Observable` 模型运行在主线程（`@MainActor`）。
- 仓储是符合 `Sendable` 的结构体，内部使用 GRDB 的异步读写。
- 解析器是值类型、没有可变状态。
- 系统回调（通知代理、NSEvent 监听等）先切到主线程，再访问界面状态。
