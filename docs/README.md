## 维护规则

- **改什么，就同步改对应的文档：**需求和范围 → 01、02；交互 → 03；结构和方案 → 04（重大取舍再在 07 中新增一条）；解析规则 → 05 和测试；流程 → 06。
- **以事实为准：**代码和文档不一致时，以验证过的事实（CI、实测）为准，修正出错的一方。
- **决策记录只追加：**07 中的条目不修改；推翻时新增一条并注明取代关系。
- **路线图状态：**阶段开始、提交验收、完成时，更新 02 中的状态。
- **新想法：**先记到 GitHub Issues（标签 `idea`），不直接写进文档。

## 术语表

| 术语 | 含义 |
|---|---|
| 面板 | 点击菜单栏图标或按快捷键弹出的主界面 |
| 模式 | 面板顶部「便签｜待办」的切换，同时决定输入的类型和列表的内容 |
| 快速输入框 | 面板顶部用来记录的输入框 |
| 便签 | 自由文本，可以多行 |
| 待办 | 一行标题，可以完成，可以带时间 |
| 全天待办 | 只有日期、没有具体时刻的待办 |
| 逾期 | 时间已过但还没完成 |
| 置顶 | 让便签排在列表最前面（和"钉到桌面"不是一回事） |
| 钉到桌面 / 桌面卡片 | 把便签变成屏幕上一个独立的小窗口 |
| 自动隐藏 | 鼠标离开后卡片淡出并允许点击穿透，鼠标靠近时再浮现 |
| 最近删除 | 已删除但还没永久清除、可以恢复的内容 |
| 阶段 / S 编号 | 路线图中的交付阶段和能力编号，如 S1-04 |
| demo | 参考项目 Reminders MenuBar（GPL-3.0） |
