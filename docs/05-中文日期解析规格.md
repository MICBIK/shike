# 05 · 中文日期解析规格

> 状态：生效中 ｜ 更新：2026-09-25
> 本文件是 `ShikeDateParser` 的行为规格，也是测试的唯一来源：§9 用例表的每一行都必须有对应的自动化测试。修改规则时，必须同时修改本文件和测试。

## 1. 作用与边界

- 只在**待办模式**下使用：输入过程中实时识别时间并高亮（S2-01），提交时从标题中去掉时间文字（S2-02）。
- 目标是覆盖日常最常见的说法，而不是穷尽中文。识别错了，用户可以一键取消（[03 §4](03-交互设计.md#4-快速输入)）。
- 规则的取舍原则：**宁可不识别，也不要识别错。**

## 2. 输出

| 字段 | 含义 |
|---|---|
| `date` | 目标时间。带时刻时为具体时刻；全天时为当天 00:00 |
| `hasTime` | 是否确定到时刻。出现具体时刻、时段词或相对时长时为是 |
| `matchedRanges` | 命中文字的区间（UTF-16 编码），按位置排序、互不重叠：日期部分和时刻部分各一个，相对时长为一个 |

没有识别到任何时间时返回空。

## 3. 基本约定

- **日历：**固定使用公历，一周从周一开始；时区为系统当前时区。**结果与系统的区域、日历、"一周的第一天"设置无关。**
- **基准时间：**调用时传入的"现在"。下文用例默认以 **2026-09-23（周三）12:00，Asia/Shanghai** 为基准，记作 T0。
- **只取一处：**一句话中出现多处时间时，日期部分和时刻部分各取最靠前的一处。
- **合法性：**日期不存在（如 2 月 30 号）、时刻越界（如 25:00、12:75）时，不识别。

## 4. 支持的说法

### 4.1 日期部分

| 类别 | 说法 | 结果 |
|---|---|---|
| 相对日 | 今天、今日；明天、明日；后天；大后天 | 当天 / +1 / +2 / +3 天 |
| 带时段的相对日 | 今早、今晚；明早、明晚 | 同上，并附带时段：早 = 早上，晚 = 晚上 |
| 若干天后 | X天后、X天之后、X天以后（X 为阿拉伯数字或中文数字） | +X 天 |
| 星期 | 周X、星期X、礼拜X（X 为一～六、日、天） | 见 §5 |
| 带前缀的星期 | 这周X、本周X、下周X、下下周X | 本周 / 下一周 / 再下一周的星期 X |
| 下周与周末 | 下周（后面不跟星期）；周末、这周末、本周末；下周末 | 下周一；本周六（今天是周六或周日则为今天）；下周六 |
| 月日 | M月D号、M月D日，可带年份 YYYY年 | 见 §5 |
| 下个月 | 下个月D号、下月D号 | 下个月的 D 号；超出该月天数时取月末 |

### 4.2 时刻部分

| 类别 | 说法 | 示例 |
|---|---|---|
| X点 | 小时用阿拉伯数字或中文数字，0～24 | 三点、15点 |
| 分钟 | 半（30）、一刻（15）、三刻（45）、整或钟（0）、X分、X（不写"分"）、零X | 两点半、三点钟、十点二十、九点零五、9点30分 |
| 冒号 | H:MM，也接受全角冒号"："；H 为 0～23，MM 为 00～59 | 15:30、9:30 |
| 时段词 | 凌晨、清晨、早上、早晨、上午、中午、午后、下午、傍晚、晚上、夜晚、夜里、半夜 | 下午三点、晚上 |

单独的"早""晚"不算时段词（避免把"早点回家"识别成时间），只在"今早、明早、今晚、明晚"中生效。

### 4.3 相对时长

X分钟后、半小时后、半个小时后、X小时后、X个小时后、X个半小时后、X.Y小时后、一刻钟后／两刻钟后／三刻钟后（后面的"后"也可以写成"之后""以后"）。结果为"现在 + 时长"，并且带时刻。

句子中出现相对时长时，只采用相对时长，不再识别其他日期和时刻。

### 4.4 时段的默认时刻与换算

只有时段词、没有具体几点时，取默认时刻；有具体几点（记作 h）时，按下表换算成 24 小时制：

| 时段 | 只有时段时 | h 的换算 |
|---|---|---|
| 凌晨 | 05:00 | 12 点 → 0 点；其余不变 |
| 清晨 | 06:00 | 不变 |
| 早上、早晨（含今早、明早） | 08:00 | 不变 |
| 上午 | 10:00 | 不变（上午十二点即中午 12 点） |
| 中午 | 12:00 | 1～5 点加 12；其余不变 |
| 午后 | 14:00 | 1～11 点加 12 |
| 下午、傍晚 | 下午 15:00，傍晚 18:00 | 1～11 点加 12 |
| 晚上、夜晚（含今晚、明晚） | 20:00 | 5～11 点加 12；0～4 点和 12 点为**次日凌晨**（0 点、12 点即次日 0 点） |
| 夜里 | 22:00 | 同"晚上" |
| 半夜 | 23:00 | 7～11 点加 12；0～6 点和 12 点为**次日凌晨** |
| 无时段（裸时刻） | — | 1～6 点视为下午（加 12）；7～11 点视为上午；0、12、13～23 点不变；24 点即次日 0 点 |

"次日凌晨"只在句子中说明了哪一天时生效，例如"今晚一点"为明天 01:00；没有说明哪一天时，按 §5 规则 1 取最近的将来时刻。

日期部分自带时段（如"明早"）而时刻部分没有时段时，使用日期部分的时段；两者都有时，以时刻部分为准。

## 5. 顺延规则

用户记待办时，说的通常是将来的时间。以下规则决定结果是否顺延到将来：

| # | 情况 | 规则 |
|---|---|---|
| 1 | 只有时刻，没有日期 | 取今天的该时刻；若不晚于现在，顺延到明天 |
| 2 | 周X（没有"这周、本周、下周"等前缀） | 取本周的星期 X。全天：该日早于今天时顺延一周（当天不顺延）；带时刻：该时刻不晚于现在时顺延一周 |
| 3 | 月日，未写年份 | 该日（按天比较）早于今天时，顺延到明年同月同日；当天不顺延 |
| 4 | 这周X、本周X、下周X、下下周X、下周、周末 | 不顺延，按字面计算 |
| 5 | 相对日（今天、明天等）、若干天后、下个月X号、写了年份的月日 | 不顺延；时间已过就照常返回，界面标注"已过" |
| 6 | 相对时长 | 现在加时长 |

## 6. 歧义与误识别

中文里的"X点"也表示"X 条"（"有两点需要注意"），"点"还会和后面的字组成词（"点心"）。按以下规则，**不把**这些"X点"识别为时刻：

| # | 规则 | 示例 |
|---|---|---|
| A1 | "X点"前面是"第" | 第一点、第3点 |
| A2 | "X点"前面是"有、这、那、共、另" | 有两点需要注意、这两点要改 |
| A3 | "点"后面紧跟的字能和"点"组成词：心、子、儿、滴、赞、击、名、评、菜、头、数、位、亮、燃、火、歌、单、餐、播、缀、拨、题、睛、明、破、清 | 买3点心、两点子 |
| A4 | "X点"后面紧跟表示内容的词：建议、意见、要求、问题、原因、理由、想法、注意、体会、收获、内容、说明、总结、看法、思考、改进、好处、不足、区别、事项、共识、结论 | 三点建议、两点意见 |

**例外：**"X点"前面紧挨时段词（下午两点），或后面带分钟、"半""整""钟"（两点半、三点钟）时，一定识别为时刻，A1～A4 不适用。

上述规则只影响时刻部分；同一句中的日期部分照常识别（例如"明天有两点需要注意"识别为明天、全天）。

## 7. 标题清理

提交待办时，按以下步骤从原文得到标题：

1. 删除 `matchedRanges` 中的文字。
2. 把连续的空白合并为一个空格。
3. 删除开头的"提醒我""记得"，以及结尾的"提醒我""提醒"。
4. 删除首尾的空白和标点：，。、,.;；:：!！?？~～ 以及空格。
5. 重复执行第 3、4 步，直到结果不再变化。（修订，Issue #2：结尾的标点会挡住第 3 步的匹配，"交报告提醒我。"单遍执行会残留"提醒我"。）
6. 结果为空时，改用原文（去掉首尾空白）作为标题。

识别被用户取消（界面 ✕）时的提交不做第 1、3 步：只执行第 2、4 步的空白与标点清理，标题保留全部文字、不带时间。

## 8. 暂不支持

农历；节日和节气（国庆、春节、中秋等）；月底、月初、年底；单独的"X号"（例如"15号还款"，容易和"3号楼""5号线"混淆）；"9/30""2026-09-30"这类数字日期（容易和分数混淆）；昨天、上周X 等过去的说法；重复（每天、每周一）；"X个工作日后"；"下班前""饭后"等以事件为参照的说法；英文日期。时间段只取开始时间（"三点到五点"识别为 15:00）。
